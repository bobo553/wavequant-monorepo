# 复权 K 线 Redis 缓存

本轮范围为 AKShare/Sina 的因果复权日线。周、月等周期继续从这份日线按现有规则聚合；趋势结果、账户结果与行情缓存分开。Python 代码和复权公式不变。

## 本地配置

当前 Docker 服务 `wavequant-api-redis-1`，Rust 通过 `redis://127.0.0.1:6380/0` 访问，使用 `wavequant:rust:local` 前缀。本地启动脚本已设置地址。Docker Redis 继续使用原命名卷，AOF / everysec；Compose 的 Redis 启动参数保存 1 GiB maxmemory、noeviction，独立重建 Redis 服务，不改 MySQL。

Redis 全局不主动淘汰键，避免把同实例的分布式锁和其他业务键一起删掉。K 线命名空间自行原子执行 LRU 和容量预算；实例内存不足时拒绝缓存写入并降级，不能把缓存当作行情事实库。容量配置以有效载荷字节计，Redis 实际内存还含键、索引、AOF 缓冲等开销。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `WAVEQUANT_KLINE_MAX_MIB` | 512 | K 线有效载荷总预算 MiB |
| `WAVEQUANT_KLINE_MAX_ENTRIES` | 2048 | 缓存身份数量上限，同一股票不同起点可能占多项 |
| `WAVEQUANT_KLINE_MAX_ITEM_MIB` | 16 | 单个完整日线快照上限 MiB |
| `WAVEQUANT_KLINE_INTRADAY_SECONDS` | 60 | 盘中逻辑刷新间隔，不是 Redis TTL |
| `WAVEQUANT_KLINE_REFRESH_BATCH` | 16 | 每轮后台最多对账数量，串行执行 |

## 缓存身份与数据源

数据键为 `<prefix>:market-kline-v2:<sha256>`，摘要包含复权规则版本、数据源、上游 Sina 身份、股票、请求起点、基础周期 1d、价格口径和 Python 环境路径。不包含前端图表级别、分析策略、引擎二进制版本、请求末日或当天日期，避免每日创建重复历史和重编译失去行情缓存。

因果复权按起点归一化，不能把不同起点的已复权价格直接混用；因此起点保留在身份中。同一身份保存截止读取当天的完整日线，历史请求仅截取自身 asof 前缀，并以可见价格/权限字段重新生成版本；未来新增 K 线不会仅因完整快照变长而改变过去的前缀版本。

AKShare 和 TDX 不拼接、不隐式故障回退。TDX 继续按现有本地文件校验流程读取，不经过在线 Redis 日线缓存；切回 AKShare 时复用其命名空间并重新判断新鲜度。若以后更换 AKShare 上游、币种、成交量单位或复权算法，必须修改身份中的规则/适配器版本，旧身份仅供淘汰，不能作为新源命中。不会因切换源执行 FLUSHDB/FLUSHALL。

分钟行情仍走现有独立流程；不能把分钟覆盖不足的完整策略请求当成日线缓存命中。

## 无 TTL 与收盘更新

K 线数据、LRU 和大小账本不设置 Redis TTL。数据中的 `refresh_after` 是逻辑新鲜度检查点，不负责删除历史；锁的有限租期和交易日历的 TTL 不属于 K 线数据 TTL。

- 盘中真实访问在逻辑刷新间隔到达后同步重取；热点按身份合并请求。
- 使用真实交易日历区分交易日、周末和节假日，统一上海时区。16:10 开始收盘对账，给上游发布/结算留出窗口。
- 后台每 60 秒最多处理一个批次，单批串行、不可重入；访问某一过期身份时同步刷新，无须等待整个后台队列。
- 服务停机期间不执行刷新；重启后从 Redis 的身份索引恢复，下一轮继续补齐。并不承诺所有缓存股票在 15:00 同时更新完毕。
- 日历不可用时不冒充收盘确认，逻辑检查保守回退到五分钟；后台下一轮重试。
- 上游尚未提供最新收盘、停牌等导致尾部无法证明完整时保留真实可用数据，每五分钟继续对账，不合成缺失日期的 K 线。

新浪 SDK 返回完整历史，因此本实现重新获取同源日线和因子，按现有公式完整对账并原子替换。这样既补尾部/内部缺口，也接收历史修订和复权因子修订；不是仅在旧复权序列后 append，更不是声称网络只传缺失部分。若上游返回的历史缺少旧快照已存在的日期，拒绝覆盖并保留最后快照，避免部分响应造成历史丢失。历史删除修订须由明确的规则/缓存身份迁移处理。

## 原子性、容量与失败

Lua 在同一操作中检查刷新锁所有者、清理失效索引、执行容量淘汰并发布新快照。分布式锁具有随机令牌、有限租期和比较释放；租期失效的旧写者不能覆盖新快照。单进程也有有界分段互斥和取消/等待超时。

LRU 只由真实访问推进；后台更新保持原有访问分数，不把冷股票人为变热。刷新期间被容量淘汰的身份不会被后台重新塞回 Redis。超过单项上限的结果直接使用，不纳入缓存。Redis 出错时熔断 30 秒，回退到最多 64 MiB / 256 项的本地缓存和原有有界 SDK 容量，旧数据仍须通过逻辑新鲜度校验，不把过期数据伪装成最新。

通过既有基础设施健康接口的 `adjusted_market_cache` 查看预算、命中、来源读取、错误及后台对账计数。结构化日志包含 `kline_cache_redis_saved`、`kline_cache_source_timing` 和后台未完成提示。
