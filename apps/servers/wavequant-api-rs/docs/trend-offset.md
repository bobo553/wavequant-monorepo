# 趋势偏移续算

默认 `trend_offset_enabled=true`。`/api/akshare-backtest` 和 `/api/tdx-backtest` 接收同名可选查询参数，传 `false` 即关闭趋势状态机的跨调用续算，每次从0重算；结果缓存仍可命中。诊断比较必须换用未缓存的请求身份。原生分析配置使用 `config.kernel.trend_offset_enabled`。查询值只接受 `true`/`false`，开关参与任务规范化身份和结果缓存键；规则/引擎/配置身份变化不复用旧状态。共享查询选项定义在 @repo/contracts 的 TrendExecutionOptionsSchema，当前页面不增加技术控制项。

## 下标与起点

返回偏移是上一趋势起点在本级结果数组中的位置，作为直接上一级输入的偏移。K线坐标、全局PointId、分路径局部位置不可混用。全局输入偏移经过确认/可知日筛选与按path分组后，转换为各路径的局部位置；未确认点和未来可知点不进入趋势计算。

趋势整波函数维护自己的 preceding_start，不再被六态的破位key覆盖。折线六态首次建立方向时记录实际方向起点，翻转时记录前一方向起点；几何和六态公式不变。此前接口中的 dynamicDataIndex 可能因起点口径修正而变化，不能把旧偏移数值作为判断结果等价的断言。

## 状态恢复

每条来源路径最多保存一个偏移前检查点和一个末尾状态。检查点包含方向、origin/extreme/key、区间极值树、待确认状态、已闭合点和事件，不重新复制行情数组或递归展开证明。恢复时核对保留的完整PointId前缀，任何较早修订、截断或配置变化都不能被偏移掩盖。

- 初次无状态：从0计算，同时在读取offset对应点之前保存检查点。
- 纯追加：保留完整末尾状态，从已处理长度继续；该状态比偏移处更靠后，无需重复读取未变化数据。
- 尾部修订：有合法检查点且其位置不晚于传入偏移时，从检查点位置恢复并包含该位置重算，之前的状态/结果保留。
- 检查点之前修订、无合法检查点或开关关闭：从0重建。仅保存一个检查点时，较早修订没有更旧状态可回退。
- 偏移前移但没有该位置的快照：可保守使用更早的合法检查点，不跳过尚未计算的输入。

来源兼容对象在边界导入PointArena时保留相同前缀的PointId，仅为修订尾部生成新点号。内核同样供一、二、三级使用，不能根据级别分叉算法。

## 性能边界

当前结构模式API每次新计算仍新建Analyzer，完整折线完成后调用一次一级趋势。初次计算没有历史检查点，偏移不会让它跳过必需历史。Worker常驻不代表其中Analyzer跨请求常驻，本轮不新增跨请求计算状态缓存。预计收益主要在复用同一个TrendCursor处理追加和尾部修订；不能将此计时称为页面首次请求提升。

compute_indices仍检查/分组完整来源，六态和连续性观察仍可能扫描历史；统计中的scanned_points只表示趋势状态机实际遍历点数。检查点状态复制、前缀核对、兼容输出物化的开销计入基准，不宣称全链路线性增量或零复制。

## 本轮对比

固定输入差分及本次授权计时已完成，结果见下文。对比使用同一份桂林2135根行情及已确认折线来源，冷计算、追加、尾部修订、早期修订分别采样，开关两模式比较完整KernelFrame。API单独对比初次新计算，避免缓存复用和取数波动冒充算法提速。Python、复权公式和启用层级不变。


## 实测结果（2026-10-24）

固定桂林旅游2018-01-01至2026-10-23的2135根K线，提取1455个已确认折线点（VO共1456点，其中发展点不参与本级闭合来源），每种场景/开关5次计时取中位数，比较完整KernelFrame。

| 场景 | 关闭偏移(ms) | 开启偏移(ms) | 解释 |
| --- | ---: | ---: | --- |
| 一次冷计算 | 2.971 | 2.738 | 均扫描1455点，小差异不作为续算收益 |
| 连续16个追加前缀 | 36.647 | 11.970 | 对从零基线少67.3%；旧代码已有纯追加游标，不把全部收益算作新增偏移收益 |
| 连续8次尾部修订（不含初始建状态） | 15.083 | 5.300 | 少64.9%；本轮新增的偏移恢复路径 |
| 连续8次早期修订 | 26.004 | 24.686 | 均从零重算，无偏移减算收益 |

尾部修订检查点为来源数组1417，单次从1417包含该点读取至1455，共38点；8次修订主循环扫描304点，关闭时11640点。统计原值还包含初始建立状态的1455点，分别1759与13095。前缀比较/分组/六态和兼容结果导出仍计时，不能声称整个函数只访问38点。各场景5次完整输出一致，一、二、三级差分检查一致，开关切换、截断、早期修订和越界拒绝已覆盖。

API另做一次预热（排除Worker冷启动），再交替false/true各3次全新计算；每对参数除开关及任务ID相同，资金100021至100023只用于避免结果缓存，交易关闭，页面原设置未动。新计算分析均非0，未把缓存复用当提速。

| API指标中位数 | 关闭(ms) | 开启(ms) |
| --- | ---: | ---: |
| 分析 | 65.326 | 73.767 |
| 后端总计 | 662.830 | 636.315 |
| HTTP读完JSON | 800.336 | 795.047 |

首次API没有历史状态，分析未提速；本组分析开启高8.441ms，可能包含检查点创建和运行波动，不推断所有冷计算固定增加该数值。后端总计/HTTP差异受取数和保存波动影响，不归因于偏移收益。当前页面每次新建Analyzer，因此不会自动获得上述尾部续算的65%收益。需要未来跨请求增量会话时另行设计有界状态缓存，本轮未引入。

开关两模式的完整state与dataVersion相同；与修改前相比，绘图data、六态和行情版本相同，dynamicDataIndex从[1439,120,0,0]修正为[1417,121,0,0]，对应前趋势起点与六态key分离的元数据修正，不宣称整个旧state完全相同。
