# 量化平台 v0.3：能力契约与验收边界

更新：v0.4 已增加统一运行、持久本地告警、账户归因报告、拒单／撤单链路和 PaperVenue 显式公司行动。以下正文保留 v0.3 原始边界；这些增量以 `docs/operations_contract.md` 为准，未因此获得真实券商或策略盈利认证。

## 目标与架构

把主控理论做成可核验的研究／纸面执行系统，不把形态解释、合成成交或测试数量当成超额收益证明。默认生产研究规则仍为：翻空为多 → 空多交替 → 确认多头趋势 → 后续新 N → 当前轧空或强轧空。未改成放宽条件的高交易频率策略。

```text
通达信 CSV + 来源元数据 ── 数据清单／当时可知证券事实／日历检查
                                      │
已有主控理论函数 ── 历史批量回测         └─ 就绪门禁（缺资料不通过）
       │
       └─ StrategyRuntime ── SIGNAL_INTENT ── PaperIntentExecutor
                                                    │
                       PortfolioLimits ── OrderService / 本地事件账本
                                                    │
                           PaperBridge ── 独立 PaperVenue 账本
                                                    │
                                  成交回报 → 对账 → 停机／人工恢复

输入与源码指纹 → ExperimentRegistry → 固定规则滚动／成本／容量报告
```

本轮是原创的单账户本地实现，参考以下官方设计，不复制受限制许可的源码：

- [NautilusTrader 对账设计](https://nautilustrader.io/docs/latest/concepts/reconciliation/)：启动／运行中的订单、成交和持仓核对，异常不直接当作已解决。
- [LEAN 现实建模](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/key-concepts)：成交、费用、滑点、购买力、结算分开建模。
- [Qlib 实验管理](https://qlib.readthedocs.io/en/stable/component/recorder.html)：记录实验、参数、运行状态与产物。
- [vn.py](https://github.com/vnpy/vnpy)：事件驱动和交易网关分层可作为未来接入参考，本项目没有声称已接入该框架。

## 时间、价格与证券事实

事件时间必须有时区，统一存 UTC；交易日用 Asia/Shanghai。日线 CSV 中无时区的日期在可用时间审计中解释为当日 15:00。盘中接口不得这样处理，必须显式传入真实可用时间。

信号价格沿用既有复权口径；新订单和纸面场所只用原始股数、原始价格。`PaperIntentExecutor` 要求显式给出当时已知的 `adjustment_factor = adjusted / raw`，将参考、止损、目标统一除以该因子，不把复权等价数量当作原始持仓。原日线回测仍是复权数量近似，不等价于新现金分红账本。

证券事实 JSON 数组示例（仅展示格式，不能作为真实证券资料导入）：

```json
[
    {
        "symbol": "EXAMPLE",
        "effective_from": "2026-01-01",
        "effective_to": null,
        "known_at": "2025-12-31T15:00:00+08:00",
        "sector": "example_sector",
        "active": true,
        "suspended": false,
        "st": false,
        "buy_lot": 100,
        "tick_size": "0.01",
        "settlement_days": 1,
        "source": "replace_with_verifiable_source"
    }
]
```

effective 区间左闭右开；先按当时已知时间过滤，再选择最新生效快照，修订只能在其 known_at 后使用。新快照过期后不恢复旧的无限期状态。接口不会替输入补齐停牌、ST、退市状态。日历 JSON 是日期字符串数组，必须由使用者提供有来源的交易所交易日；本系统不从股票行情日期并集推断官方日历。

## 订单／风险契约

- BUY/SELL 为只做多账户的买入／卖出已有持仓，不支持卖空。信号必须早于订单；日线意图执行只允许后续交易日。
- 每股仅一张活动单；买单从接受到撤单确认／成交完成之前占用未成交金额及剩余费用预算。撤单请求不是撤单成功，撤单途中成交仍接收。
- 订单身份和成交身份幂等。相同 ID、不同内容报错，绝不静默覆写。成交不能超过余量，不能超限价或费用预算。费用预算不足的真实回报不得丢弃为“无成交”：桥接器记录事故并停买，等待对账与处置。
- 限价价格使用证券 tick；买入按整手向下取量。风险股数以原始开盘价、原结构止损及费用计算；零手输出明确拒绝原因。开盘重新检查 gap 和费用后盈亏比，不修改理论止损来凑够手数。
- 单股、行业、总敞口含活动买单的未成交部分。卖单不会提前释放风险敞口；无有效证券资料或行情则不买入。行情过期时退出也可能被拒绝，必须恢复行情或使用经审批的真实券商应急路径，本项目没有后者。
- T+1 定义为买入交易日之后才允许卖出；真实非交易日由上游日历控制。本地订单服务不把日期变化等同于交易所开市。
- `expires_on` 必须来自调用者的交易日／机会有效期规则。过期入场记录 EXPIRED；入场拒绝只有一次机会。退出因 T+1／不可交易等拒绝时保留待处理，不把退出意图吞掉。
- 高水位基于明确调用 `monitor()` 得到的估值观察，不是连续市场价格高水位。调用方需要在每个有效估值时点运行监控；不能宣称具备未启动的后台实时监控。
- 停买不阻止回报入账；恢复需要成功对账与显式人工理由。金融状态改变后旧对账凭据失效。不会自动改现金／持仓来“修平”差异。
- 公司行动只接受来源明确、已知的净现金权益及股份比率；有活动单先处理单据，零碎权益需外部确认。该接口不猜测股息税、不自动认购配股；独立 PaperVenue 暂不处理公司行动，不应宣称已做完整权益对账。

## 恢复与对账运行手册

1. 停止新入场；保留账户、场所、登记库及日志，不要删除未处理订单来恢复运行。
2. 用 `journal-check` 验证哈希链。损坏则从已核验备份恢复到新路径；不要在原库修改历史事件。
3. 用原资本与风险配置重开 `OrderService`；配置不一致将拒绝恢复。重放确定持仓、现金、活动单和事件状态。
4. 纸面场所调用 `PaperBridge.dispatch()` 可重复投递相同订单 ID；`receive()` 幂等补收已持久化回报。此策略只适用于内置幂等本地场所，不可照搬到未知券商网络。
5. `reconcile()` 对照独立场所的现金、持仓和活动单；不一致即停买，差异证据留在 RECONCILIATION／HALT 事件中。终态后迟到成交、超预算、倒序账务等进入人工事故处理，不提供自动伪造修复。
6. 一致后人工审阅原因并调用 `resume(..., operator_reason=...)`。之后仍须满足行情、仓位、回撤等门禁。
7. `journal-check account.sqlite --backup new-backup.sqlite` 使用 SQLite backup API，不能只复制活跃库的主文件而丢失 WAL。备份文件已存在则拒绝覆盖。

哈希链只能发现相对当前记录内容的损坏；不能防止有文件写权限的人重写整条链或删除文件。生产应外部锚定摘要、分权访问、离线备份。当前没有这些安全保证。

## 研究验收

固定规则 rolling 默认训练 756 个观察日、验证 252 日、测试 126 日，两段间隔使用协议 max_hold_bars（当前 40）。目前不训练模型、不选参数，train/validation 标记是留给后续模型选择的边界，不伪称已做优化。每个测试窗独立空仓，保留此前因果历史热身；测试窗不重叠，窗尾持仓估值不强平。间隔不是任意标签泄漏已被清除的证明。

全区间成本与容量压力是另一组独立诊断，不和滚动窗口结果拼接。bootstrap 沿用 20 日块、1,000 次固定种子；无多重检验校正。零交易返回无成交证据而非有效零收益；交易不足即未建立优势。人工 annotation 接口的空集合返回 unavailable，不返回满分。

所有实验记录数据／元数据／协议／源码／测试／依赖声明指纹，记录开始及完成／失败。输入运行中改变不允许成功完成；产物可再次验 hash。指纹不是文件内容归档，需要另外备份输入原文件。注册库拒绝复用 run ID，输出目录不得覆盖既有结果。

## 性能与部署边界

当前 SQLite 单写事务 + 全量事件投影、逐前缀信号重算以正确性为先，复杂度不适用于高频或大规模实时全市场。没有微服务、Web 面板、用户鉴权、通知服务器和券商密钥存储。它是可运行、可故障验证的基础设施增量，不是与成熟开源交易引擎等规模、等可靠性的认证。先验证数据和策略边际价值，再有依据地做缓存快照、增量计算和执行网关迁移。
