# 转多与空多交替结构搜索

## 目标

结构搜索用于从本地通达信目录或封存研究样本中查找近期新确认的结构地标。它只帮助研究者缩小复核范围，不产生买点、订单或交易建议。

## 支持的结构

- `bear_to_bull`：空翻多高点。该高点必须严格突破同级冻结末跌高，并保留已确认空头低点和关键位证据。
- `bear_bull_alternation`：空多交替低点。该低点必须来自已经合格的空翻多阶段，并满足 Core 中的较高回档与严格小于 `2/3` 等确认条件。
- `any`：在同一次搜索中返回上述任一新确认结构；每条结果仍保留自己的实际结构类型。
- 两类结构均可搜索一级、二级、三级，或者一次搜索全部级别。

## 时间口径

每个结构同时保留两个日期：

- `event_date`：高点或低点实际发生的交易日。
- `available_at`：完整证据最终可知的确认日。

搜索窗口只使用 `available_at`。例如一个高点发生在 8 月 3 日、到 8 月 9 日才确认，则它只会进入包含 8 月 9 日的搜索窗口，不会在 8 月 3 日的历史回放中提前出现。

窗口 `1 / 5 / 20` 表示截至回放日期的最近 `1 / 5 / 20` 个真实交易日，不是自然日。

Core 同时输出 `session_age`：确认日在当前股票交易日序列中的倒数位置，`1` 代表回放当天确认。后台只需生成一次最近 20 个交易日、全部类型和全部级别的宽快照，API 即可无损裁剪出 1/5/20 日查询。

## 数据边界

- 通达信搜索读取与当前原始行情图一致的本地 `.day` 数据，不依赖复权成交模型，因此创业板、科创板和北交所也可以参与结构搜索。
- 封存样本使用对应策略版本生成的理论结构，但仍只搜索 Core 输出的正式地标。
- 搜索启动后会固定行情文件版本和 Core 代码版本；运行中任一版本变化都会使整批结果失效，避免混合新旧口径。
- Core 的逐股扫描仍是可取消的计算执行器，但只由后台 Worker 或管理员兜底入口调用。面向用户的查询不启动扫描，也不接受部分结果。

## 预计算与版本更新

- Worker 以通达信证券目录、最新交易日和每个 `.day` 文件版本生成行情 SHA-256 指纹。
- `wavequant-core` 全部 Python 源码内容组成独立算法指纹；结构规则、确认逻辑或数据适配代码变化都会产生新版本。
- 后台以运行、策略、回放日、行情指纹和算法指纹生成幂等快照 ID。只有同一版本没有完成快照时才计算。
- 计算完成后由 API 的 SQL 仓储一次性发布；进程中断、行情中途变化或算法中途变化均不会覆盖上一个可用快照。
- 常驻 Worker 周期检测数据版本。代码发布必须重启 Worker，使新代码加载并自动生成新算法版本快照。

## 展示边界

Web 只提交查询条件、显示已完成快照并定位图表。结构定义、级别、发生日、确认日和证据全部来自 Python Core，浏览器不得自行补点、推断趋势或触发全市场计算。
