# WaveQuant：从量化研究原型到商业产品的完整路线图

规划日期：2026-09-09。适用假设：中国大陆 A 股、日线／中低频、只做多；现有通达信数据与主控波浪体系为研究起点。本次仅规划，不授权采购、云部署、通知客户、公开收费、接入真实账户或交易。

## 一、目标与判断

推荐定位：**可解释、可复核、可追溯的 A 股量化研究与复盘工作台**。先在一个细分场景做到专业，不同时追求高频、全球资产、AI 全自动基金和大众荐股平台。

“最佳”不等于功能最多或历史收益最高。评价维度应是：数据可信、规则可解释、研究可证伪、执行可对账、风险可控制、服务可恢复、用户持续付费、业务合法合规。没有工程功能可以保证未来盈利。

两条路径必须分开：

1. **研究工具商业化路径**：复盘、实验管理、用户自有数据与策略分析、机构内部研究工具。验证的是工具价值、准确性和可用性；仍需按实际功能接受法律审查，并非冠以“工具”就天然豁免。
2. **投资交易能力路径**：策略形成有代表性的样本外证据 → 持续模拟 → 经批准的小规模自有资金试运行 → 审慎扩容。对外提供具体证券建议、自动跟单、代客执行或资产管理，另有资质和业务边界，不能靠免责声明替代。

工具可在策略尚未证明盈利时提供合法、透明的研究价值；不能以此宣传该策略能赚钱。投资路径停在证据不足状态，不妨碍合规的工具验证，但阻止收益型营销和实盘扩张。

## 三、阶段路线与验收闸门

以下是约 4—6 名核心成员、数据授权及时到位时的规划窗口，不是工期报价。阶段可并行；验收未过不得因日期到了就升级。完整清单是多年演进上限，不要求付费 MVP 一次实现 140 项。

| 阶段                     | 参考窗口          | 主要交付                                                         | 出口条件                                                                   |
| ------------------------ | ----------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| R0 定位与基线            | 第 1—2 周         | 能力盘点、用户访谈、产品边界、研究协议、授权清单                 | 用户／市场／资金假设明确；旧结果冻结；商业风险有负责人                     |
| R1 可信研究底座          | 第 3—8 周         | PIT 数据、金标准、规则状态机、版本统一、完整诊断                 | 宣称范围内无未解释缺口；关键时间／价格／规则用例通过                       |
| R2 策略证据与组合        | 第 9—16 周        | 新版全池分层研究、对照、滚动、组合、成本与资金适配               | 有可复核研究结论，包括失败结论；未达到证据标准不晋级交易                   |
| R3 工具试点＋持续模拟    | 第 4—6 月         | 合规研究工具试用、用户空间、配额、任务服务；连续模拟             | 工具：真实使用／付费意愿与安全验收；交易：过程与对账合格且机会样本仍需够用 |
| R4 商业 V1＋受控执行验证 | 第 7—12 月        | 研究工具收费运营、企业试点；另行审批券商沙箱／自有资金小规模验证 | 工具：授权合同、计费支持、恢复可用；交易：各前置闸门通过及明确账户授权     |
| R5 商业复制与专业化      | 第 12—18 月及以后 | 可复制部署、续费、企业 SLA；按证据扩策略和容量                   | 单位经济成立、客户留存、合规安全审查；资金扩容由容量与真实交易证据决定     |

投资路径的 G2／G3 可以长期不通过。不得为了按期上线，把“没有证据”改写成“通过”。研究工具试点不应默认开放当前的商业买点推荐或跟单功能。

### 闸门定义

- **G0 业务与知识产权**：数据、代码、讲义素材、商标、客户用途均有授权／适用性结论；书面限定可卖与不可卖功能。
- **G1 数据和实现正确性**：声明股票池内的应有记录均覆盖或有原因隔离；时间可知性、退市与停牌、复权现金／股数核对；独立标注和核心性质测试通过。
- **G2 研究证据**：预登记目标、试验数、样本边界、成本、停止条件；与合理基准比较；考虑相关性与多重尝试后评估经济／统计证据。不设“满 30／100 笔就有效”的机械规则。
- **G3 模拟执行**：建议至少 60 个完整交易日作为运维观察起点，但时间和交易样本是双条件；零机会不能假装验证了真实策略执行。合成故障测试与真实信号模拟分别报告。
- **G4 真实执行准入**：券商支持、账户所有人授权、适用报告流程、独立风险预算、应急责任人、停机与对账演练、密钥安全均通过；先满足所用策略的 G2，不用真实资金补做基础正确性测试。
- **G5 收费产品准入**：功能法律审查、行情展示／分发权、数据隔离、安全、服务合同、营销材料、计费退款、客服与恢复演练通过。它不是 G4 的替代物。
- **G6 扩容准入**：实测成交成本、容量、风险集中度、服务成本与留存支持扩张；未通过则降规模、暂停或退役。

## 四、140 项功能与非功能待办

以下均是尚待新建、补齐、验证或产品化的工作，不表示相关基础模块不存在。P0＝研究正确性或发布前硬门禁；P1＝核心闭环；P2＝商业成熟度；P3＝证据和需求支持后扩展。优先级必须结合阶段：例如实盘密钥安全是实盘前 P0，不要求纯本地研究阶段立即采购密钥服务。

每项进入开发前补齐：负责人、用户价值、依赖 ID、输入／输出契约、验收用例、估算、发布与回滚方式。模块验收不能替代单项测试。

### A. 产品定位与研发治理（产品负责人；R0 起）

- [ ] A01 P0：确认首批用户、市场、频率、只做多边界和不提供的服务。
- [ ] A02 P0：盘点现有模块，区分已实现、未接通、模拟验证、真实验证。
- [ ] A03 P0：冻结讲义 V1，建立不可覆盖的策略卡与版本晋级记录。
- [ ] A04 P0：建立假设登记、全部试验历史及未通过结果保留机制。
- [ ] A05 P1：统一名词字典、规则 ID、参数定义和中文理由目录。
- [ ] A06 P1：为每个待办建立依赖、责任人、验收、成本与风险。
- [ ] A07 P1：定义研究、模拟、交易、产品四套分离的就绪评分。
- [ ] A08 P1：建立策略变更审查、双人复核与发布审批流程。
- [ ] A09 P1：建立问题复盘、数据事故和模型失效的知识库。
- [ ] A10 P2：建立季度继续／暂停／转向评审，按证据调整范围。

验收：新成员能回答每条规则为何存在、何时修改、谁批准、哪份结果对应哪版代码。

### B. 数据平台与历史真实性（数据工程；R1 核心）

- [ ] B01 P0：补齐有来源的历史证券主表、代码变更和上市退市记录。
- [ ] B02 P0：补齐当时 ST、停复牌、板块及特殊交易状态。
- [ ] B03 P0：接入官方交易日历、交易时段和按生效日期版本化规则。
- [ ] B04 P0：建立包含退市股的历史股票池，禁止用今天名单回看全部历史。
- [ ] B05 P0：补齐分红、送转、配股、权益到账和复权因子的核对链。
- [ ] B06 P0：采购／接入可授权分钟或更细行情，记录覆盖与缺失。
- [ ] B07 P1：建立第二数据源差异核查和冲突隔离，不静默混用。
- [ ] B08 P1：建立原始、清洗、研究三层数据及可知时间／修订版本。
- [ ] B09 P1：实现增量更新、质量告警、重跑、来源血缘与修订影响分析。
- [ ] B10 P2：按需加入公告时点财务、行业、指数成分和其他有授权特征。

验收：每个用于决策的字段能追溯来源、有效时间、当时可知时间；未覆盖证券明确隔离。通达信继续保留为本地导入器，不自动变成商业数据分发权。

### C. 理论规则与特征引擎（量化＋领域标注；R1—R2）

- [ ] C01 P0：建设独立人工标注集，包含正例、反例、争议例与标注者一致性。
- [ ] C02 P0：逐项核对突破、N、交替、六态与讲义示例的实现差异。
- [ ] C03 P0：用真实次级行情检验母子顺序约定，不把约定当真实路径。
- [ ] C04 P0：统一收盘确认、盘中观察、未来确认及同日点的时间语义。
- [ ] C05 P1：定义一二三级结构分别作条件、标签或显示时的独立接口。
- [ ] C06 P1：接通正负扭转的真实次级连线确认，未知时输出 UNKNOWN。
- [ ] C07 P1：完善洗盘、头底疑虑、三六分力道的可解释证据输出。
- [ ] C08 P1：将门槛设为可预登记假设，区分必要条件与辅助评分，不无脑全 AND。
- [ ] C09 P1：实现逐棒增量状态机，和当前批量参考实现做差分检验。
- [ ] C10 P2：接入有依据的多周期特征；ABC、五顶十满公式未明确就不臆造。

验收：事件 precision／recall 与确认延迟在独立标注集上报告；失败归因到规则而不是靠改参数掩盖。人工一致性低时先修理论定义，不用机器指标掩饰。

### D. 研究与策略有效性（量化研究；R2 持续）

- [ ] D01 P0：把新版接入既有研究、实验登记及滚动管线，禁止沿用旧策略成绩。
- [ ] D02 P0：设定未使用的股票池／时间锁箱、访问日志与一次性评审流程。
- [ ] D03 P0：设定现金、指数／持有、简单趋势及风险暴露匹配的基准。
- [ ] D04 P0：升级全流程泄漏检测，包括特征处理、标签重叠与历史修订。
- [ ] D05 P1：建立分层抽样评估，报告行业、大小盘、流动性、年份、市场环境。
- [ ] D06 P1：开展预登记消融：N、交替、量能、盘态和退出条件各贡献多少。
- [ ] D07 P1：将既有多重检验／重采样扩展为跨版本的试验审计与选择偏差评估。
- [ ] D08 P1：评估有效独立样本和统计功效，不以表面交易笔数代替样本量。
- [ ] D09 P1：建立参数邻域、成本、延迟、流动性及容量稳健性报告。
- [ ] D10 P1：建立研究失败、策略退役和冠军／挑战者晋级机制，不默认选收益最高者。

验收：研究报告可得出“不成立／证据不足”；所有试验留痕；结论对合理基准有解释。区间净收益、年化、净超额收益、检验 p 值和未来概率不能混用。

### E. 回测与仿真真实性（引擎工程；R1—R3）

- [ ] E01 P0：明确新信号、批量回测、流式模拟、OMS 的统一输入输出契约。
- [ ] E02 P0：补按历史日期的板块／新股／涨跌幅／整手规则，未支持板块不交易。
- [ ] E03 P0：统一可知时间、订单创建、成交、结算与权益到账时序。
- [ ] E04 P0：把复权等价回测与原始现金股数账本做逐日差异核对。
- [ ] E05 P1：加入价差、滑点和成交量参与约束，参数来源独立于收益优化。
- [ ] E06 P1：仿真部分成交、撤单竞争、排队和未成交，未知队列不保证成交。
- [ ] E07 P1：接入分钟回放，处理同日止盈／止损先后和集合竞价不确定性。
- [ ] E08 P1：增加信号延迟、断流、网络延迟、缺行情与执行失效情景。
- [ ] E09 P1：用另一实现或已知答案小样本交叉验证关键现金和成交计算。
- [ ] E10 P2：提供回测、模拟和实盘差异报告，逐项标定而非统一“补滑点”。

验收：相同输入、版本与随机种子可复现；价格、现金、股数、费用及订单状态守恒；不强行把未成交变成已成交。

### F. 组合构建与风险管理（量化＋风险负责人；R2—R4）

- [ ] F01 P0：将新版放入真实共享资金组合，明确并发信号竞争而非相加个股收益。
- [ ] F02 P0：建设资金可执行性矩阵：不同账户规模下整手、风险和仓位约束。
- [ ] F03 P1：设计候选优先级与交易成本感知排序，排序规则单独登记。
- [ ] F04 P1：补行业、相关性、风格、流动性和单事件集中度检查。
- [ ] F05 P1：建设波动率目标和风险预算分配，与现有固定预算做对照。
- [ ] F06 P0：交易前、中、后的统一风险检查，并计入未成交订单占用。
- [ ] F07 P0：建立亏损／回撤／异常频率触发的停买、撤单和人工恢复。
- [ ] F08 P1：建立跳空、连续跌停、停牌、流动性枯竭和相关性上升压力测试。
- [ ] F09 P1：评估策略容量、拥挤和资金增加后的成本恶化，不按比例外推收益。
- [ ] F10 P2：在独立策略有证据后开展多策略风险分配、现金与再平衡管理。

验收：一手也买不起时明确返回不可执行；不自动增杠杆或放宽止损。止损只是退出规则，不保证最大实际亏损。

### G. 实盘执行与账户账务（执行工程＋账户负责人；R3—R4，受准入限制）

- [ ] G01 P0：选择一个有明确权限与文档的券商接口，先完成沙箱／测试环境验证。
- [ ] G02 P0：实现券商订单 ID 映射、重启查询和未知状态隔离，不盲目重发。
- [ ] G03 P0：处理回报重复、乱序、漏报、部分成交、拒单、撤单及撤成竞争。
- [ ] G04 P0：实现启动、盘中、盘后现金／持仓／活动单／成交四方对账。
- [ ] G05 P0：接通真实费用、税费、公司行动、资金入出和账务日结。
- [ ] G06 P0：验证断线重连、凭据失效、行情陈旧、系统切换与应急人工通道。
- [ ] G07 P1：建立仅观察的影子运行，再到经审批小规模运行的明确切换流程。
- [ ] G08 P1：建立预期价格与真实成交偏差、未成交机会和执行质量报告。
- [ ] G09 P1：提供账户授权、只读／交易权限分离、撤销授权与凭据轮换。
- [ ] G10 P2：第一网关稳定后再支持多券商／多账户，严禁账户状态互相串用。

验收：对账不一致即隔离／停买，真实成交仍必须入账；恢复需要责任人与理由。任何真实交易均另行取得账户所有人的明确授权。

### H. 研究工作台与复盘体验（前端＋产品；R1—R3）

- [ ] H01 P1：把每只股票的未满足条件做成逐级诊断，不只显示“匹配 0”。
- [ ] H02 P1：展示“规则满足／资金可执行／信号已失效／成交”四种不同状态。
- [ ] H03 P1：升级 B/S 点击证据，展示实际数量、费用、拒单及原始决策时间。
- [ ] H04 P1：提供策略版本差异和图形差异对照，定位哪条规则导致变化。
- [ ] H05 P1：提供日周分钟联动、确认日期标识和跨周期同步回放。
- [ ] H06 P1：提供人工标注、争议审核、案例收藏与复盘笔记。
- [ ] H07 P1：提供组合净值、基准、风险、成本和持仓归因工作台。
- [ ] H08 P2：提供实验过滤、报告比较、参数视图与一键复现入口。
- [ ] H09 P2：完善大量图层性能、键盘操作、无障碍、移动只读与布局保存。
- [ ] H10 P2：提供数据／策略版本化分享与导出，分享权限和市场数据授权可控。

验收：用户从候选列表到订单原因可以独立完成复核；图层开关不改变策略结果；图形好看不能掩盖没有交易或数据过期。

### I. 计算平台与 API（后端＋平台工程；R2—R4）

- [ ] I01 P1：模块化现有代码，拆清领域核心、数据适配、计算、展示和执行边界。
- [ ] I02 P1：为行情、事件、策略配置和结果建立稳定 schema 与 API 版本。
- [ ] I03 P1：将内存扫描任务升级为持久队列、取消、恢复、超时和失败可见。
- [ ] I04 P1：增加增量特征缓存，缓存键包含行情、参数、代码和可知时间。
- [ ] I05 P1：加入确定性分片并行和资源限制，确保并行不改变排名及结果。
- [ ] I06 P1：按性能证据迁移分析存储与多用户元数据，保留旧快照可复现。
- [ ] I07 P0：多用户下实施租户隔离、授权校验、对象访问控制与请求限流。
- [ ] I08 P1：提供受控 Python SDK／批量接口，避免让客户运行任意服务器命令。
- [ ] I09 P2：提供任务成本、耗时、失败率、缓存命中与资源使用追踪。
- [ ] I10 P2：建立可迁移部署和数据库升级／回滚，按实际负载决定是否拆服务。

验收：声明硬件、数据量和并发数后测 p50／p95，不能以一只股票耗时宣称全市场实时。

### J. 安全、运维与服务可靠性（SRE／安全；R3 发布前重点）

- [ ] J01 P0：建立威胁模型，覆盖行情投毒、策略代码执行、密钥和租户泄漏。
- [ ] J02 P0：实现登录、角色权限、多因素认证和敏感操作二次授权。
- [ ] J03 P0：建立密钥安全存储、最小权限、轮换、脱敏与访问审计。
- [ ] J04 P0：用户策略代码若上线，必须有进程／容器隔离、资源和网络限制。
- [ ] J05 P1：把本地告警接到经授权的外部通道，验证告警送达与确认升级。
- [ ] J06 P1：建立交易时段／任务心跳、时钟偏差、数据新鲜度和模型漂移监控。
- [ ] J07 P0：建设加密异地备份与隔离恢复演练，明确数据保留与恢复目标。
- [ ] J08 P0：执行依赖漏洞、供应链、配置安全和渗透测试，建立修复时限。
- [ ] J09 P1：建立事故分级、值班、停机预案、演练与客户状态沟通。
- [ ] J10 P2：为不同产品定义 SLA／SLO、容灾与容量计划，公开范围和免责边界。

验收：无未处置严重安全问题；恢复不是“备份文件存在”。研究 API 可先以月度 99.5% 可用性作为讨论目标，交易系统须另按交易窗口和券商链路定义，不能共用一个百分比承诺。

### K. 测试、审计与可复现交付（QA＋独立复核；所有阶段）

- [ ] K01 P0：把现有测试接入真实 CI，关键分支失败阻止发布。
- [ ] K02 P0：扩展金融性质测试：无未来、资金股数守恒、顺序和幂等。
- [ ] K03 P0：建立历史股票池、复权、交易限制的独立已知答案夹具。
- [ ] K04 P1：建立批量／增量／模拟／真实适配器的差分与契约测试。
- [ ] K05 P1：为筛选、回测、分享、计费和权限建立完整用户路径测试。
- [ ] K06 P0：覆盖断网、进程崩溃、数据库恢复、乱序回报及重复请求故障演练。
- [ ] K07 P1：建立全市场与多用户压力、长稳、内存和资源泄漏测试。
- [ ] K08 P1：固定依赖、环境镜像、输入快照和产物签名，做到可再运行。
- [ ] K09 P0：发布前提供变更影响、已知限制、证据清单和人工签字记录。
- [ ] K10 P2：外部审阅关键模型、账务和安全；建立客户审计证据包。

验收：测试数量只是辅助指标；重要不变量和失败路径必须覆盖，未测范围明确列出。

### L. 商业产品与经营（产品／销售／客户成功；R0 验证，R3 起交付）

- [ ] L01 P0：访谈目标客户，验证其研究／复盘痛点与现有替代方式。
- [ ] L02 P1：定义个人本地、研究团队、企业私有化产品边界和需求优先级。
- [ ] L03 P1：设计账号、组织、项目空间、成员协作和权限申请。
- [ ] L04 P1：实现套餐、试用、席位、计算额度、资源限额和升级降级。
- [ ] L05 P0：接入合法支付、幂等计费、开票、退款与订单对账。
- [ ] L06 P1：提供新手流程、示例项目、帮助中心、使用培训和工单。
- [ ] L07 P1：建设用户激活、留存、转化、续费、流失原因指标。
- [ ] L08 P1：建立企业 PoC、验收清单、部署手册和支持分工。
- [ ] L09 P1：测算数据许可、计算、存储、支持和销售后的贡献毛利。
- [ ] L10 P2：形成行业案例与渠道合作，只宣传可证实能力，不精选收益误导。

验收：建议先约 10—20 位目标用户访谈、5 位设计合作用户、2—3 家付费试点作为学习目标；不是市场预测。价格由付费试验确定，不先拍脑袋制定“荐股会员价”。

### M. 合规、数据与知识产权（法律／合规负责人；R0 起，发布前 P0）

- [ ] M01 P0：由专业顾问按实际功能确定软件、投顾、交易技术或资管边界。
- [ ] M02 P0：核验通达信及其他数据的下载、存储、展示、派生和再分发权利。
- [ ] M03 P0：审查讲义、Notion 图片、内部教材与名称使用授权，保存证据。
- [ ] M04 P0：建立开源 SBOM、许可证、NOTICE、修改与分发义务清单。
- [ ] M05 P0：核验 TradingView 具体产品、部署与收费场景的授权条件。
- [ ] M06 P0：评估适用的程序化交易报告、券商测试和持续信息更新流程。
- [ ] M07 P0：对用户协议、风险揭示、隐私、个人信息与数据保留出具审查结论。
- [ ] M08 P0：评估目标部署地的备案、网络安全、数据跨境及合同义务。
- [ ] M09 P0：审查买点推荐、收益宣传、自动跟单、佣金分成与客户资金接触。
- [ ] M10 P1：建立法规／授权变更台账、续约预警、投诉处置和合作方尽调。

验收：收费前有书面审查和合同，不以“仅供参考”视作已经合规；每增加资产、地区、客户类型或金融功能，重新评估。

### N. 进阶研究、生态与可选扩展（R5 以后，全部需求驱动）

- [ ] N01 P3：为另一类低相关策略建立独立证据，不让平台只能容纳一个理论。
- [ ] N02 P3：建立经授权的因子库、因子检验及可解释打分模型。
- [ ] N03 P3：引入机器学习的训练／特征版本和线上漂移治理，先打败简单基线。
- [ ] N04 P3：增加 AI 研究助手，输出来源与不确定性，不直接授予交易权限。
- [ ] N05 P3：建立第三方策略插件契约、沙箱、审核及供应链控制。
- [ ] N06 P3：在法律评估后讨论策略市场，不默认销售证券买卖建议。
- [ ] N07 P3：扩展 ETF 等产品时重做交易制度、数据与适用性模型。
- [ ] N08 P3：增加融资、做空、期权、多币种或境外市场前分别立项，不混入当前只做多系统。
- [ ] N09 P3：有业务需求与实测瓶颈后再采用高性能语言、分布式计算或低延迟设施。
- [ ] N10 P3：建立企业生态、可审计 API 伙伴与定制交付规范，控制长期维护成本。

验收：每个扩展单独有用户价值、授权、成本和风险论证。高频、强化学习、社交跟单与多市场不是成为优秀中低频工具的必选项。

## 七、商业化方案与法律边界

### 推荐顺序

1. **设计合作试点**：少量研究者／小团队，验证数据清洗、案例复盘、实验复现与报告交付价值；不出售“盈利保证”。
2. **研究工具付费版**：按席位、项目、计算额度和支持范围收费；个人本地版与团队版分开，数据费用和使用权单列。
3. **企业私有化**：部署费、年度软件许可、维护与支持；验收流程、SLA、数据隔离和升级成本必须标准化。
4. **受监管业务合作**：若提供具体证券建议或交易服务，先完成业务定性、许可／合作方尽调和合同责任设计，再讨论商业形式。合作持牌机构不自动解决全部责任。
5. **自营能力扩张**：单独以实际交易净表现、容量与风险控制评估，不把软件收入和账户投资收益混为同一业绩。

公开规则说明，向投资者提供涉及具体证券分析、价格预测或买卖时机建议的软件并直接或间接获益，涉及证券投资咨询业务监管。当前“符合买点股票列表”尤其需要在对外收费前进行功能级审查；叫“研究工具”、由用户点击确认，均不能自动排除监管适用。[证监会投资者保护局答复](https://www.csrc.gov.cn/csrc/c100028/c1002326/content.shtml)。该答复为历史监管说明，正式上线仍需由专业顾问核验现行完整规则与实际业务。

程序化交易也不能等同于“只有高频才受管理”。证监会《证券市场程序化交易管理规定（试行）》自 2024-10-08 起施行；沪深交易所实施细则自 2025-07-07 起施行。是否需要报告、如何测试和持续管理，应由账户所属券商与法律合规顾问按实际系统和交易方式确认。[证监会公告](https://www.csrc.gov.cn/csrc/c101954/c7480579/content.shtml)、[上交所现行细则页面](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml)、[深交所发布通知](https://www.szse.cn/lawrules/rule/trade/t20250403_612770.html)。

不碰的早期模式：未经许可收费荐股、承诺保本或收益、共享客户账户密码、代收客户交易本金、伪造实盘曲线、把回测最佳案例当全部客户实际收益。这里是规划风险提示，不是正式法律意见。

### 经营衡量

- 激活：能独立导入数据、跑出可复现结果、解释一笔信号或拒单的用户比例。
- 使用：有效研究项目、复盘完成率、重复使用与协作，而非单纯访问量。
- 收费：试用到付费、续费、流失原因及企业试点到正式合同。
- 经济：收入扣除行情许可、算力、存储、支付、支持和交付后是否有合理贡献毛利。
- 风险：错误结果、不可恢复事故、越权访问、违规宣传和未处理投诉。

产品门槛和统计门槛应在试点前声明，但不把通用的留存率或 Sharpe 数字当成行业认证。不同产品需要不同基准。

## 八、人员、预算与停止条件

建议核心角色：量化研究／领域负责人 1，数据工程 1，回测／执行工程 1，全栈产品工程 1，测试／SRE 1；产品与客户访谈由负责人兼任，法律、财务、安全审计按阶段投入。早期可以一人兼岗，但关键策略审批、真实账户权限与审计应分工。

预算分开核算：人月成本 + 历史与实时数据授权 + 计算存储网络 + 安全／法律／审计 + 客户支持／销售；试运行投资资金不是研发费用，也不能靠客户交易本金支付研发。先获取数据与接口供应商书面报价，再确定年度预算。个人开发按相同路线缩小功能范围，不照搬 4—6 人团队的日期。

明确停止／转向条件：

- 数据或材料无法取得相应授权：不发布有关内容／数据功能。
- 理论标注长期无法达成一致：缩减或重新定义规则，不以回测选解释。
- 预登记研究反复没有足量机会或净优势：冻结为研究案例，退役交易候选；只有另立假设才能继续探索。
- 交易异常无法可靠对账与停机：禁止真实交易上线。
- 用户不愿为研究效率持续付费：调整定位／范围，而不是改卖未经证实的收益承诺。
- 定制与数据成本使单位经济不成立：停止扩客户，先标准化或缩小服务。

最后的完成标准不是“140 个勾全部打满”，而是：在明确范围内，研究真实可信、策略结论诚实、执行安全可控、客户得到可验证价值，并且商业模式合法且可持续。
