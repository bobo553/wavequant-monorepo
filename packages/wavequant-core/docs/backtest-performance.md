# 回测性能验证

性能改动必须保持同一输入下的完整信号、审计、订单、成交、权益与收益一致。原始行情浏览和因果复权账户使用不同的价格基准、起点和缓存身份，不能互相替代。

## 定位方法

先在实际慢任务上采样，区分行情 I/O、信号生成、分钟入场准备、退出风险准备、逐日撮合和结果序列化。采样比例只用于定位，不能当作各阶段的精确秒数。使用 `cProfile` 和 `pstats` 查看固定输入的调用次数、累计耗时和调用方，再独立计时；分析器本身会增加开销。

首次计算、信号缓存命中和完整账户缓存命中分别计时。记录 Python 版本、源码版本、日线根数、日期范围、策略、执行参数、价格基准和输入摘要。外部请求不纳入纯计算提速数字，分钟覆盖不足仍遵守原有拒绝或日线回退规则。

## 优化边界

- 先减少重复日期解析、来源解析和趋势历史计算，再考虑并行；并行不能补偿多项式增长的重复工作。
- 复用仅限已核验的同一数据、参数、知识时钟和路径。短前缀必须重新检查当时可知来源，不能裁切最终确认结果代替历史观察。
- 缓存有明确容量和所有者。可变输出须与内部缓存隔离，修订行情、不同起点、N 开关、部分日线和调用方修改均不能污染另一计算。
- 保留全部证明、交易权限、复权因子和风险门禁；不能通过扩大超时、缩短历史或省略证据来满足性能目标。
- 回归优先检查重复解析和历史构建的次数，以及新旧结果的完整差分。机器上的秒数另作基准，避免脆弱的毫秒级单测断言。

## 离线基准

在 Core workspace 的项目环境中执行以下命令。`research.json` 是 `encode_research` 格式的固定日线与信号记录；`config.json` 包含实际 `strategy`、`execution`；分钟快照包含 `symbol` 和以交易日为键的 `sessions`，保留原始分钟字符串。可选 `upstream_session_dates` 单独保存上游的实际覆盖日期；缓存可读日与上游覆盖日不能混为一谈，否则缺日回退证据会发生变化。基准禁止网络连接，不能用完整窗口信号裁切生成较短窗口的缓存结果。

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_backtest_replay.py `
    --research research.json --config config.json --minutes minutes.json `
    --sizes 64,128,all --mode both --repeat 2 --timeout 120 --reuse `
    --output benchmark-results
```

每个 worker 使用独立进程和指定的源码树，记录输入与源码运行前后的摘要。冷计算从该窗口的完整行情重新生成信号；缓存计算只使用该窗口自己的已完成冷计算输出。`--source-root` 指向冻结的完整 `src`，用于旧版和候选版对照；`--compare` 指向旧版 `summary.json`，逐字段核对信号和完整账户结果。`--profile` 用于单独定位调用次数，其秒数不能与未启用分析器的基准混比。超时、缺少有效前缀信号和结果差异如实记录为未完成，不能计作通过。

## 官方依据

- [Python 性能分析器](https://docs.python.org/3.14/library/profile.html)：分析调用频率与耗时，分析器用于定位，基准需独立计时。
- [Python 缓存规则](https://docs.python.org/3.14/library/functools.html)：缓存持有输入和结果的引用；有副作用或每次必须生成独立可变对象的函数不适合直接缓存返回值。
- [Python JSON 类型转换](https://docs.python.org/3.14/library/json.html)：标准字典的顺序保持，但非字符串键及特殊数值不能直接套用普通 JSON 模板。模板只用于已冻结、具体类型受支持的标准证据；每次导出生成独立容器。

第一版完整日线图表回放耗时 679.874 秒，五个阶段共写约 2.504 GB 临时行；这版仍未达到完整回测两分钟的目标。短样本中的复用收益不能代替完整验收。完整输入的一级点超过 8 MiB 时，LRU 会在重复顺序扫描中持续淘汰上一轮的点，已作为容量回归场景单独检查。

优化分为三处：同一请求复用已核验的每日历史；来源未变时复用不可变几何判断、已关闭路径的独立资格；标准证据从只读模板生成独立副本。轧空触发审计更新后，从原始每日几何重新计算确认、失效与成熟事件，不能叠加旧合并结果。不同来源、价格、权限、复权、起点、参数或 N 模式必须重新取证。

离线分钟缓存快照保留 2026-08-04 至 2026-10-09 的 43 个完整交易日，并独立记录实际上游覆盖日期。其他日期缺少分钟数据时仍按原协议明确回退；该基准不声称验证外部分钟源的网络耗时或完整覆盖。实际旧账户的分钟入场只有两次部分日线信号请求，第一次包含 2,102 根日线并重新计算整段趋势，第二次才可复用相邻日前缀。这项计数由旧成交证据核对，只用于定位，不作为性能基准。

追加判断和分钟检查点接入后的首轮冻结完整冷回测仍未通过：120 秒截止时处于信号生成阶段，峰值工作集 1,180,266,496 字节；没有完整输出，也没有执行后续三轮缓存或冷计算。该结果不能记为完成或提速。早期采样与对象计数发现，每日拐点历史累计创建 760,748 对相同的不可变点，原图占 231,747,576 字节，保存时再次深复制同等图。

修复上述重复对象后的第二版正式完整冷计算仍在 120 秒截止时生成信号，但峰值已降至 128,868,352 字节，未产生完整账户。后续 180 秒采样诊断仍处于层级历史，不能将扩大的诊断时限当作验收。512 日独立 cProfile 定位到私有借用准入函数重复遍历标准证明树：2,009 次调用、约 950 万次 pop 和 535 万次 id，分析器累计 11.427 秒；这些秒数只用于定位。下一步为相同完整 typed 点的有界准入认证复用，修订、类型、键序和未知对象仍需重新认证或回退。
