# 符合买点的股票列表

刷新工作台 → 右侧“符合买点” → 选择信号窗口 → “扫描买点”。

## 定义与范围

2026-09-09 当前默认策略为“分级双买点 V2”，规则见 `strategy_lecture_v2.md`；V1、旧严格版及代理版保留对照。本次实时展示只改扫描传输与列表更新，不修改买点判断。

- 默认“回放当天 · 新信号”：该股票日线必须更新到指定回放日；原策略在当天收盘产生 LONG，且当时个股独立回测账户未持仓。不会把已有持仓的移动止损更新当成新买点。
- 只复用当前“趋势交替后轧空 / 强轧空”的策略信号，不创建另外的放宽版筛选公式，不自动从严格版退回代理版。
- 买入信号还没有通过下一开盘的价格、费用后盈亏比、现金、仓位、数量等执行检查，不能理解为成交保证。
- 近 5 / 20 根窗口列出各股票最近一个符合历史入场条件的信号，并区分已模拟成交、执行被拒绝、后续已失效、历史未成交。历史信号不冒充当前有效买点。
- 通达信模式扫描本机执行模型支持的沪深主板股票；不支持板块、当前 ST / 退市名称、没有日线、日线尚未更新的证券分别计为跳过，不当作“已验证不符合”。历史非 ST 假设、除权等价份额限制沿用原回测。
- 封存样本模式扫描所选实验中的股票，使用各股独立回测，而非共享组合的实际持仓分摊。通达信使用输入起点；封存样本沿用快照起点。

## 交互和数据一致性

列表显示中文名、信号日期、盘态、原始参考价、相对量、收盘参考盈亏比及执行状态。参考价由统一的复权等价价除以信号当日因子得到。

点击股票会切到对应来源的个股回测，保留扫描日期、策略和成本，定位到 LONG 信号，展示趋势链证据。不是定位到一个编造的 B 成交箭头。数据或引擎运行 ID 已变化时提示重新扫描。

修改回放日期、策略、成本、数据来源、起点或信号窗口，会清空旧结果并请求取消旧扫描；仅切换选中的股票，不作废同一股票池的扫描。

扫描在本机后台逐股进行，页面显示已处理 / 总数、匹配、失败、过期和跳过数量。运行中及取消后的列表明确标记为部分结果。取消在当前股票计算结束后生效。计算不会发送真实交易。

找到一只即发布一次可读进度，唤醒页面追加显示，不等待后续股票或整批扫描结束。已有股票按钮不重建，保留点击、焦点和列表位置；同日第二类买点仍优先排序。网络中断保留已显示结果并重连，取消保留部分结果，数据完整性失败则清空作废结果。

行情版本与除权文件在扫描期间改变，或源码修改，则作废结果，避免把不同时间的数据混成一次筛选。任务状态在服务进程内保存，重启后需要重新扫描；网络失败不宣布扫描完成。

## 接口契约

仅增加本机研究任务的创建和取消，不开放数据写入或交易接口：

- `POST /api/buy-scan`：JSON `{run, variant, scenario, source, asof, start, lookback}`。`source` 仅为 `tdx` 或 `snapshot`，`lookback` 仅为 1、5、20。
- `GET /api/buy-scan?id=...`：立即读取 `revision, status, params, total, processed, skipped, failed, stale, results, errors`。
- `GET /api/buy-scan?id=...&after=N`：等待版本高于 N，有新匹配或进度即返回，最长 20 秒返回一次现状；等待释放扫描锁，不阻塞计算和取消。前端收到即渲染并续接下一次等待，不再固定间隔轮询。版本递增可避免取消响应和进度响应乱序使状态倒退。
- `funnel.stocks` 为各类股票数（可重叠），`funnel.events/rejections` 为所选窗口内的事件／拒绝评估次数，不能相加当成股票总数。
- `POST /api/buy-scan/cancel`：JSON `{id}`。
- 所有接口保留 loopback Host / 同源检查；POST 必须是小型 JSON，不接受任意文件路径。
- 同时只运行一个扫描；同参数重复请求返回原任务，不同参数须先取消。最多保留最近四个任务。
