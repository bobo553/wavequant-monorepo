# v2 零成交排查、v3 预检查与 v4 盘态路径完善

## 先区分三种零

- 无合格入场信号：由理论／结构／量能过滤造成，不能当成成交引擎故障。
- 有信号但全拒单：检查实际价格、目标、费用、整手、风险预算及资金／流动性。
- 已买入但尚未平仓：平仓笔数为零不等于没交易；必须检查 `entry_fills` 与期末持仓。

引擎仍用真实现金和持仓计算净值；不把零改成虚假收益。但报告必须显示上述状态，零成交自动无法通过现有研究门槛。

## v2 实际证据

严格折线组全历史未发 LONG：缺少次级路径的内外包会中断结构，11 个完整多头许可后未同时满足后续新 N、轧空、量能和价格条件。不能为了交易编造缺失日内路径。

日线代理完整组 11 次 LONG 全部未成交：

| 原拒单标签       | 次数 | 核验                                                                         |
| ---------------- | ---: | ---------------------------------------------------------------------------- |
| 费用后盈亏比不足 |    5 | 使用实际滑点开盘价、冻结止损和首个未达目标；不是费用符号错误                 |
| 现金或容量不足   |    5 | 均为 600519 的风险预算不足一手；另有两次单股权重也不足一手，日志原来没有拆分 |
| 开盘目标耗尽     |    1 | 开盘已越过旧目标，不能按昨日价虚构成交                                       |

例如 2024-02-06 的 000651，实际开盘毛盈亏比约 1.387，未计费用已经低于 1.5；拒单正确。五次高价股可承受风险股数约 51.7、82.4、73.9、29.5、34.7 股，均低于一手 100 股。日线量以原始股数保存，调整价与等价数量的换算经核对没有多除一次因子的错误。

## 真正需要改的衔接问题

v2 在信号收盘剩余空间已经不足时，仍提交 LONG 并立即消耗该 N 的唯一入场机会；执行层拒单后，后来合格的阶段也不能被策略评估。虽然符合原“一次发单”实现，却混淆了“形态观察”与“可执行入场”。

v3 使用明确的三阶段：**形态候选 → 收盘价格预检查 → 一次发单、次日实际复核**。

1. 用户确认的翻空为多、空多交替、多头趋势、后续新 N、当前轧空／强轧空条件全部保留。
2. 用当前收盘、冻结轧空低、首个尚未观察达到的目标计算毛盈亏比。低于原 1.5 门槛，只记 `entry_preflight_rejected`，不消耗该 N。
3. 可以继续观察，但必须再次出现当日合格盘态，重新满足所有原有过滤。不使用昨日盘态、不倒填信号、不自动降低入场价。
4. 不允许为通过检查直接跳到远目标。只有近目标已在历史中实际观察达到，原规则才推进到下阶段。
5. 一旦真正提交 LONG，仍只有一次次日尝试，不把拒单改成无限重试。实际开盘的费用后盈亏比仍要求 >=1.5，风险预算／整手／权重／资金／量能限制全部保留。
6. 收盘预检查仅是计划价格过滤，不预测次日开盘，也不声称通过后一定能成交。它会放弃“昨日不合格但次日大幅低开才合格”的订单，是明确的新工作流约定。

## 可诊断性修复

`orders.csv` 不再丢失详细字段：记录参考价、成交试算价、止损、目标、毛／净盈亏比、费用后收益／损失、要求门槛、复权因子、现金、权益、风险预算、每项约束对应原始股数、限制来源和一手资金／风险。

零手拒绝拆为 `risk_budget_below_one_lot`、`position_weight_below_one_lot`、`liquidity_below_one_lot`、`cash_below_one_lot`、`cash_after_fees_below_one_lot`，不再笼统归咎于现金。

新增 `execution_diagnostics.json` 与报告执行健康表，分开无信号、全部拒单、仅未平仓、已有平仓；`entry_fills` 不再被平仓计数替代。

## 固定对照，不用收益倒推修复

新协议 `configs/system_squeeze_v3.json` 在回测前固定；数据仍为相同十股、2018—2026-09-07 的已观察历史。主组严格折线、代理完整、v2 关闭预检查对照、v3 关闭量能诊断。后两组都不是自动选优的候选上线策略。

没有扩大股票篮子、提高风险预算、取消 100 股整手、降低盈亏比或用未来拐点制造成交。旧 v1/v2 配置与报告保留，缺省未声明预检查的历史协议按关闭解释。

```powershell
.venv\Scripts\python.exe -m wavequant.interfaces.cli system-research --protocol configs/system_squeeze_v3.json --output-dir results/system_squeeze_v3_20260908
```

工程用例验证“首次不合格观察不会耗尽、目标确实推进后产生非空信号并在下一开盘成交”，同时验证未推进目标不能跳级、前缀不变、零手原因及零成交状态。真实回测是否成交／盈利，必须另看本次结果，不能由测试通过推断。

## v3 复测发现：事件不能代替完整盘态

v3 的严格与代理完整组仍无成交。修正发单生命周期没有凭空产生收益，结果如实保留在 `results/system_squeeze_v3_20260908`。

进一步对照原文“被迫压回后，不破轧空低点并持续出现上涨”发现：策略只消费“收盘创新高”的六态确认事件，没有消费此前已经成立的轧空在回压后恢复上涨这一分支。创新高确认可证明某日状态，但不应成为该盘态下唯一的入场触发。

v4 为这条原文分支增加独立策略观察 `squeeze_pullback_resume`，底层六态观察器不改写：

1. 同一正 N 在多头许可后形成，并已有真实的轧空或强轧空确认事件，距当前至少两棒；不能从盘坚、未知或未完成 N 推断。
2. 自攻击起轧空低和波段边界始终未破；历史上一度破过后来收回也不复活本次机会。
3. 昨日收盘低于最近确认轧空时的收盘，证明有回压，不能把一路上涨也叫回档。
4. 今日低点 >= 昨低，今日红棒收盘严格突破昨高，证明局部恢复上涨；等于昨高、继续创新低或阴棒都不通过。
5. 当前仍须具备同一已完成空多交替的多头许可，满足原 N 的量能、回档、首个未达目标、预检查、下一开盘实际净盈亏比与风险容量。

该恢复状态记作普通“轧空”，不把经历回压的状态标为强轧空；事件审计明确 `confirmation_source=pullback_resumption`，不伪装成底层创新高确认。强轧空／新高轧空原路径仍保留。止损仍用原轧空低，不人为拉近以放大手数。

这是在看到 v3 结果后的、依据理论补充的探索性策略假设，不是新的独立样本外，也不宣称是唯一正确的六态解释。v4 的固定组为严格完整、代理完整、仅创新高路径对照（v3）、原发单方式对照（v2），全部保留量能。

```powershell
.venv\Scripts\python.exe -m wavequant.interfaces.cli system-research --protocol configs/system_squeeze_v4.json --output-dir results/system_squeeze_v4_20260908
```

当前默认命令指向 v4；重跑必须更换空目录。原 v2/v3 的协议、报告及已有结果不覆盖。
