# 二级趋势线

输入仅为已经确认的一级趋势线点，不重新计算原高低折线，不更改一级线算法。

## 取点与连线

1. 最近两组一级高低点同时抬升／降低后建立初始多／空背景；混合、相等或样本不足时等待，不凭空补起点。
2. 空头段跟踪最低一级低点，其左侧最近一级高点为该段“末跌高”。只在创新低时更新这组参考，不随中间的小反弹滚动替换压力。
3. 已确认一级高点严格突破该末跌高，发生“翻空为多”：把此前整段最低点确认为二级低点。突破点是确认依据，不一定是二级高点。
4. 多头段对称处理：跟踪最高一级高点及其前一个一级低点（末升低）。后续已确认一级低点严格跌破末升低，发生“翻多为空”，此前整段最高点确认为二级高点。
5. 二级高点另有一条受限升级通道：确认二级低点的翻空为多高点如果同时严格突破上一正式二级高点（即旧二级末跌高），先记为升级候选；它之后的第一个已确认一级回撤低点必须高于本轮二级低点，且回撤幅度严格小于上涨段的 `2/3`；随后一级波段递推器还必须确认出一个高于本轮二级低点的非正式二级反转低点，候选高点才在该反转的可知日升级为正式二级高点。突破当日、回撤发生日和非正式低点的价格日期都不能提前倒填确认。
6. 二级 L → H → L 按发生位置依次连接，一条实线可以跨过多个一级高低点。同向只更新候选极值；不把未确认尾端画成已确认实线。相等仅为触碰，不确认转换。

普通的一级关键位突破通道仍不额外等待 67% 回档；只有上述“突破旧二级末跌高后升级高点”的第二通道必须同时具备严格小于 `2/3` 的场景回撤和非正式二级反转确认。二级层只消费一级层正式输出：一级已经用真实确认极值完成的跨路径衔接可以参与二级计算；一级仍保持断开的区间不会由二级自行补点。

中大力德样本中，`2022-08-03 H70 49.56` 在确认 `2022-05-27 L9 13.16` 的同时突破上一正式二级高点 `2021-12-01 H8 27.71`；`2022-08-30 L71 29.75` 的回撤比例为约 `54.42%`，严格小于 `2/3`；发展递推随后把 `2022-12-23 L76 22.06` 确认为非正式二级低点，该证据到 `2023-02-06` 才可知，因此 H70 也只从 `2023-02-06` 起成为正式二级高点。

## 时点与展示

- 紫色、较粗实线，无端点圆圈；编号 `Ⅱ·L1`、`Ⅱ·H1` 仅按序，不套用讲义示例。可独立开关，与一级浅蓝实线、原黄／青虚线并存。
- `time` 是极值实际发生日期，`source_level1_available_at` 是该一级点原确认日，`available_at` 是最终确认链完成日。普通通道取后续一级关键位突破点的确认日；高点升级通道取非正式二级反转点的确认日。历史回放只能以当时可用的一级点计算。
- 点击二级点展示被突破的一级末跌高／末升低、确认突破的一级点及日期。选中水平线从可知日开始，不提前画到历史。
- 二级线也可计算其自身高低结构和关键位，但这与形成它的一级突破依据分开标注。结果只用于讲义图表，不自动加入策略、订单或回测。

### 当前末跌高换锚

二级实线点一经确认不会改写，但“当前二级末跌高”会随已经发生的结构失效而换锚。对窗口内原最低二级低点，只在该低点已经可知之后，市场收盘从不低于该点严格穿越到其下方时确认失效；盘中最低价越线或收盘相等都不成立。失效时，如果右侧已经有可知的后续二级低点，则当前段切换到最晚的该低点，其左侧最近二级高点成为新的末跌高。Python 在对应二级 stroke 的 `key_transitions` 返回旧低、旧关键高、新低、新关键高、收盘跌破 K 线和因果日期，Web 仅按图窗截止日期消费该事实。

华夏银行样本中，`2026-01-23 L34 6.32` 在 `2026-08-31` 由前收盘 `6.55` 到收盘 `6.23` 严格跌破；当时 `2026-06-29 L35 6.34` 已于 `2026-08-04` 确认，因此当前二级末跌高从 `2025-07-10 H33 8.72` 换锚为 `2026-04-02 H34 7.52`。

接口字段 `secondary_trends`：`trend_level=2`、`source_level=1`，每个点保存 `source_level1_position`、`confirmed_on_level1`、`confirmed_by`、`broken_key`、`flip`，可复核它跨过了哪些一级点；通过第二通道升级的高点另带 `alternation`（起点、突破高、回撤点、比例）和 `provisional_reversal`（非正式二级反转点）。每条 stroke 的 `key_transitions` 保存当前末跌高换锚证据，根级 `key_transition_count` 给出事件数量。
