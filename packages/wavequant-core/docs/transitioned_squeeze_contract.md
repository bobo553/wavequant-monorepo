# 多头趋势中的轧空入场（v2）

本文件保留 v2 的趋势时序约定。当前默认 v4 保留 v3 的“不合格价格观察不消耗 N”预检查，并单独补充“已确认轧空、回压不破防守、局部恢复上涨”的原文分支，见 `squeeze_zero_fill_diagnosis.md`。原趋势交替、量能、止损、风险参数不变，默认命令输出目录改为 v4。

本版按用户确认，将“多翻空”修正为“翻空为多”。默认入场策略为 `transitioned_squeeze`，不是修改底层六态定义。旧 `legacy_n_continuation` 只保留用于历史对照。

## 必须依序成立

1. 在明确的 120 棒结构窗口中，以已确认高低点得到空头趋势，冻结当时的末跌高与低点，不能事后重选更容易突破的颈线。
2. 后续收盘首次严格越过冻结末跌高，记录“翻空为多”。等于压力不算突破。
3. 突破后的首个确认高点及其后首个确认低点给出回档比 `(高点-回档低点)/(高点-该升段起点)`。严格介于 0 与 67% 才确认“空多交替”；等于 67% 不通过。沿用基础结构模块的字面 67%，不偷换成 N 过滤中的精确 2/3。
4. 当前最近两个确认高点、两个确认低点分别严格抬高，才获得多头入场许可。此确认可与第 3 步在同一收盘发生，但不能早于它。
5. **新的正 N 攻击棒必须严格晚于第 4 步**，且攻击当日和信号当日均拥有同一段多头许可。旧 N 后来才确认轧空不能补买；窗口趋势混合或未知时暂停许可。
6. 信号当日六态必须为轧空或强轧空；盘坚一律排除，也不能沿用已消失的历史盘态标签。
7. 原量能、N 回档、目标、费用后盈亏比、仓位、执行与退出条件继续成立。洗盘／正扭转来源标签不能绕过上述门槛。

日线右侧确认有延迟，始终使用 `confirmed_index`，不把拐点所在日当成可交易日。收盘确认信号仍最早下一开盘成交。

## 许可的生命周期与明确工程约定

- 冻结第一个可用空头背景；突破之前超过 120 棒则过期。背景已知时价格已越过末跌高的，不倒填此前突破。
- 原低点盘中失守、严格折线遇内外包未解、代理替换了尚未完成交替的冻结背景点时，撤销该观察，不跨段续接。
- 首次回档不满足 67% 则该观察结束，不跳过失败回档去寻找后来成功的一次。
- 已确认交替保留为历史事实，不随代理后来更新末端而重画。但原低失守、重新出现空头结构或收盘跌破前一棒已知末升低，会撤销许可；必须重新完成链条。
- 混合／未知结构暂停新买入，不凭此单独新增卖出规则；原有倒 N、末升低、负扭转、结构中断、止损／目标和持有期退出不变。
- 此处“多头趋势”是已定义的最近两组高低点同向抬高，不要求整个 120 棒窗口历史全部单调上涨，否则窗口内的空头起始背景会造成自相矛盾。

这些是可执行、保守的状态选择约定，不是讲义对成功率或主力意图的实证证明。ABC 三波只作为原有独立证据，不在本次新增为硬条件。

## 固定回测

新协议 `configs/system_squeeze_v2.json`，沿用同一通达信快照与 2018—2021／2022—2023／2024—2026-09-07 三段，量能与风险参数不变。

- `strict_full`：严格折线 + 新门槛，固定主策略。
- `proxy_full`：日线确认拐点代理 + 新门槛，不是严格讲义折线。
- `proxy_no_volume`：新门槛但取消量能，只有诊断用途。
- `proxy_legacy`：旧版完整代理对照，允许盘坚且无交替先决条件，不是新策略。
