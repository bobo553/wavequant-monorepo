# v0.4 代码审查记录

## 总体评价

沿用 code-review 技能的模块边界、错误处理、空状态和测试覆盖检查；本项目是 Python，不套用其前端框架专项规则。改动集中于离线运行控制、恢复、账户报告及已有纸面执行边界，未修改主控理论或入场策略。

## P0 问题

本次检查没有建立真实券商安全性结论；实盘路由保持关闭。不得将合成测试与不完整历史数据当作交易授权。

## P1 问题

- 原 PaperBridge 不投递撤单请求：已补齐持久撤单投递和成交竞争处理。
- 原拒单仅有投影分支，没有可用的场所／OMS 回报链：已补齐并测试部分成交后拒单。
- 原独立场所缺少公司行动，无法验证双账本权益一致：新增明确权益接口和对账测试；仍不推算税或配股支付。
- 数据日历检查将快照范围外日期计为缺失：已限制到快照范围。

## P2 问题

- 原缺少统一运行状态、防重复、失败记录和输入归档：新增 OperationsConfig、OS 锁、运行账本与封存产物。
- 原仅支持单库备份，缺少输入和多文件恢复验证：新增清单校验、拒绝覆盖及恢复演练。
- 原缺少可用账户归因报告：新增按时点 FIFO 成本、费用、净现金权益与净值守恒核验。
- 原告警无法确认与去重：新增本地持久告警状态；不声称已发外部通知。

## P3 问题

新增模块继续采用标准库和小型函数，避免引入框架依赖。未来需要根据真实负载证据改进全量事件投影的性能，而不是当前先做无依据的缓存。

## 建议修改顺序

先用本地验收命令建立运行与恢复证据，再接真实历史证券状态和次级行情；之后独立前瞻研究、券商沙箱和真实账户对账验收。交易权限、数据采购、通知目的地和部署环境需由用户指定。

## 已修改文件

- wavequant/operations.py、operational_store.py：统一运行与本地告警。
- wavequant/backup_bundle.py：备份与新目录恢复。
- wavequant/account_report.py：账户归因与过期价格边界。
- wavequant/order_service.py、paper_venue.py：拒单、撤单投递和独立权益记账。
- wavequant/data_catalog.py：快照日历范围修复。
- wavequant/cli.py、configs/operations.json：可执行入口。
- tests/test_operations.py：新增故障与已知答案验证。

最终执行结果以 runs/<ID>/test_log.txt、report.json、artifacts.json 和 operations.sqlite 为准，不把本说明当成测试已执行的证据。
