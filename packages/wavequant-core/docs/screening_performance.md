# 选股与图表缓存优化

## 已实现的结果

本次只优化计算和复用，不改变折线、一级/二级/三级趋势线或 V2 双买点规则。
正常点「扫描买点」即可使用，无须先执行单独的预计算命令；每只成功计算的股票立即保存，下次扫描或服务重启后复用。取消扫描不删除已经完成股票的缓存，匹配股票仍然找到即展示。

缓存位置：`data/cache/artifacts-v1.sqlite`，与原有通达信除权解码文件共用缓存目录，不写入 `D:/TDX`，不改动封存的回测报告。

## 慢的原因与对应处理

1. 原回测只有 8 项进程内 LRU：扫描几千只股票会互相淘汰，重启全部失效。现在增加 SQLite 压缩 JSON 持久缓存，内存层仅作补充。
2. 原每只股票都可能触发整个通达信目录重扫；除权 JSON 每股解析一次，再遍历筛选。现在单股只查相应市场的名称缓存；全市场目录复用未变化文件的首尾记录；除权表按内容哈希每版本解析一次并建立股票索引。
3. 同一历史前缀被 N 字、力道、扭转分析重复完整验证。现在使用只包含 frozen Bar 的不可变已校验序列；正向切片继承已验证性质，拼接或倒序不会错误继承。公开观察函数收到普通序列时仍逐项校验。
4. 选股原来必须载入完整历史账本。现在持久保存 1/5/20 交易日窗口摘要，保留原 `buy_match` 和 `funnel` 的持仓过滤、执行拒绝、信号日期与条件诊断；暖扫描直接读取摘要。
5. 打开图表原来重复生成所有形态。现在首次计算股票时就保存基础折线及一至三级趋势线，打开图表补充规则标记并缓存完整图表理论输出。
6. 原所有股票共享一个回测大锁。现在只对同股票计算进行去重锁定；不同股票的请求不再在这个锁上排队。没有宣称实现多进程并行全市场扫描。

## 缓存分层

| 数据层          | 持久保存内容                                                             | 复用范围                                              |
| --------------- | ------------------------------------------------------------------------ | ----------------------------------------------------- |
| signals         | 统一复权 Bar、交易许可、复权因子、策略信号、完整 audit、counts、会话日期 | 相同行情/除权/区间/策略，允许改变执行费用             |
| geometry        | 基础折线、一级、二级、三级趋势线                                         | 精确相同 Bar 前缀、复权口径和代码版本；与执行成本无关 |
| backtest        | 上述研究数据、成交账本、B/S 标记、收益曲线、指标和证据                   | 精确相同研究输入及执行参数                            |
| screen          | 1/5/20 日买点摘要、跳过原因、漏斗与来源                                  | 同一回测身份；窗口之间无需重跑回测                    |
| adjusted_theory | 统一复权图表的规则、N 字、形态及确认信息                                 | 相同区间、策略与行情，可跨执行费用场景复用            |
| raw_theory      | 通达信原始不复权图表及各级趋势线                                         | 单独命名空间，不与回测成交混用                        |

`engine` 当前保守地包含全部 `wavequant/*.py` 内容哈希。行情使用实际文件内容 SHA-256，而非仅凭文件名、文件长度或最后交易日。引擎文件哈希计算按文件元数据复用，但每次请求仍检查元数据变化，运行中改代码须重启服务。

## 正确性与失效边界

- 某股 `.day` 追加或修订：该股相关缓存失效，其他不变股票可继续复用。
- `gbbq` 改变：为保持一致的来源审计，目前保守地使相关回测全部失效，不假定其他股票未受影响。
- 起点、截止日、策略参数、代码、复权口径改变：隔离缓存。
- 只改变费用/执行参数：重跑成交模拟，复用策略信号和几何图形。
- 不会拿完整历史画线简单截断后冒充较早日期的因果结果。每个截止日期有独立键。
- 写入研究缓存前和返回前验证数据版本；更新中的数据不发布为可用回测。
- SQLite WAL 和事务保证写入原子性；压缩内容另有 SHA-256 校验。单条数据损坏时按未命中重新计算；缓存磁盘不可写时记录警告并返回实际计算结果，不将错误当作“无买点”。
- 默认压缩有效载荷预算 4 GiB；超限逐出最旧的可再计算内容。预算不是 SQLite/WAL 文件物理大小的绝对上限，数据库会复用空闲页，不在交易请求中执行重型 VACUUM。
- 已扫描股票会存储，不表示全市场已经预热；尚未扫描的股票第一次仍需计算。

## 固定样本实测

输入：本机通达信，2018-01-01 至 2026-09-07，`lecture_v2`、base 执行成本，固定 11 只股票。不是全市场耗时或策略收益保证。

最终证据目录：`results/cache_benchmark_20260910_final/`。

| 验证项目                                                   |                实测 |
| ---------------------------------------------------------- | ------------------: |
| 11 股首次完整研究/回测及写入缓存累计                       |            56.81 秒 |
| 同 11 股直接读取选股摘要累计                               |             0.39 秒 |
| 新 Python 进程读取 11 股完整回测累计（含首次除权索引加载） |             1.48 秒 |
| 新进程摘要读取累计                                         |             0.40 秒 |
| 真正 BuyScanner 任务处理这 11 股，含进度与版本检查         |      0.53 / 0.52 秒 |
| 上海机场/上汽/茅台纯策略计算，对照原重复校验路径           | 约 1.74–1.78 倍速度 |

以上首次计算与暖扫描经过不同路径，不能将差值称作“相同算法首次计算加速 100 多倍”。最重要的收益来自下次不用重新计算。真实全市场还包含目录准备、更多股票和冷缓存工作。

正确性验收：

- 11 股逐项比对优化前保存的 bars、signals、audit、orders、trades、metrics、curve、markers，全部一致。
- 三只代表股票用同一当前策略、原逐次验证方式对照，信号、审计和计数完全一致。
- 22 个真实行情前缀检查通过，不提前出现未来信号。
- 第 1 只股票在超过 8 股内存容量后仍磁盘命中；另起进程全部磁盘命中。
- 真实扫描的两次结果和条件漏斗一致，均 11 次缓存命中、0 次重新计算、0 失败。
- Python 全量测试 495 项通过；前端单元测试 35 项通过；实时结果列表已验证缓存统计、取消保留部分结果、失败撤销结果和连续连接线不受影响。
- 完整浏览器验收 23 组通过：`results/visualization_v1/2026-09-09T17-01-43-371Z/`；实时列表专项 6 组、二级趋势线专项 3 组通过。
- 浏览器实测茅台相同图表接口：优化前约 9.40 秒（TTFB 9.33 秒）；缓存就绪且服务空闲时 0.132–0.152 秒，HTTP 200。运行其他冷计算的并发压力下仍可到数秒，不承诺任何负载下固定响应时间。原始暖请求证据见 `browser_warm.json`。

## 仍需单独设计的下一阶段

日更新后的全市场冷计算还不是 O(新增 K 线)。要进一步减少它，需要把折线、各级趋势状态机、候选 N、待确认抵抗、持仓与挂起订单保存为可恢复检查点，并证明续算与全量重放完全相同；历史修订需要回退到修订日前的检查点。不能只补画一段线或拼接旧信号冒充正确增量。

其次是有界多进程预计算队列和收盘后预热。当前没有自动创建后台定时任务，也没有让尚未完成的全市场扫描冒充已经完成。
