# 分布式系统与高可用专项规范

本文件仅在设计跨进程、跨服务、跨区域协作，或涉及一致性、部分失败、跨服务事务和高可用目标时加载。

## 失败与一致性

- 网络调用可能超时、丢失、重复、乱序或在对端已成功后本地仍未知；“超时”不能直接等同于“未执行”。
- 按具体操作定义一致性要求，如读己之写、单调读、唯一写入或最终收敛；禁止只给整个系统贴 `CP/AP` 标签。
- 每个远程操作明确超时、取消、幂等键、重试条件、退避、最大尝试和最终失败去向。
- 重试预算要小于调用方截止时间；多层重试必须协调，避免重试风暴和超时放大。
- 只有可安全重复的操作才能自动重试写入；幂等状态和业务结果必须在同一原子边界持久化。

## 顺序、时间与事务

- 不依赖不同主机的墙钟建立全局顺序；业务顺序使用版本号、序列、逻辑时间或服务端权威状态。
- 事件明确分区键、单分区顺序、重复、迟到和重放语义；消费者不能假设全局严格有序。
- 数据库事务不跨服务。跨服务流程使用显式状态机、Saga/补偿、Outbox/Inbox 与对账，并保存可恢复进度。
- 2PC、TCC、分布式锁或共识只在一致性收益足以覆盖可用性和运维成本时采用；优先使用成熟基础设施而非自研协议。
- 补偿不是数据库回滚：必须处理不可逆外部动作、补偿失败、人工介入和审计。

## 可用性与恢复

- 从用户旅程定义 SLI/SLO，再决定冗余、切换和降级；SLA 是外部承诺，不能替代内部工程目标。
- 对数据和能力分别定义 RPO/RTO，标明故障域、单点、依赖配额、恢复顺序和降级后损失。
- 冗余实例必须跨目标故障域，并验证负载、数据复制、选主和切换；“部署多个副本”不等于高可用。
- 关键路径提供有界降级、舱壁、限流和熔断；降级不得绕过鉴权、账本或数据完整性。
- 通过备份恢复、依赖故障、网络延迟/分区和流量切换演练验证 Runbook；实验必须限定爆炸半径并有停止条件。

## 演进与验证

- 协议和 Schema 采用先扩展、双向兼容、迁移、观测、再收缩的顺序；锁步升级说明系统边界仍未解耦。
- 跨服务变更至少验证契约兼容、重复投递、未知结果、超时取消、积压恢复、部分成功和回滚。
- 记录关键请求的 correlation/causation 标识、状态转换和版本，使事故中可以还原因果链。
- 任何“Exactly once”声明都必须说明适用边界和依赖；通常以至少一次投递配合幂等处理实现业务一次效果。
