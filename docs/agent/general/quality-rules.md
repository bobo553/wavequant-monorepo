# 工程质量专项规范

本文件仅在任务涉及缺陷定位、测试策略、代码评审、重构、技术文档、依赖或开源合规时加载。具体语言和领域测试要求仍以对应领域规则为准。

## 调试与缺陷修复

- 先稳定复现并保存最小输入、环境、版本、时间和完整错误链；不能只根据最后一行报错或用户表象猜根因。
- 从边界向内收集日志、指标、Trace、网络、状态和最近变更，区分事实、假设与尚未验证的信息。
- 每轮只验证一个可证伪假设并记录结果；禁止同时改动多个变量后把“现象消失”当成根因证明。
- 优先缩小到最小复现，使用断点、结构化日志或局部诊断；临时探针不得泄露敏感数据，任务结束前必须移除。
- 修复根因而不是吞异常、增加无界重试或扩大超时。缺陷修复应先编写复现用例；修复和相邻回归的自动化测试按风险手动运行或交由 CI。
- 无法自动化复现时记录人工步骤、观察结果、剩余不确定性和后续监控，不能声称已完全修复。

## 测试策略

- 日常代码修改后按风险选择定向测试，未运行项记录为待验证。完整测试套件由 CI 或独立验证执行，不纳入每次提交的同步钩子；已运行的检查失败时先修复。
- 按失败风险选择测试层级：纯规则用单元测试，真实边界用集成/契约测试，少量关键用户链路用 E2E；不以固定比例机械分配。
- 测试遵循 Arrange、Act、Assert，名称表达前置条件、动作和预期；一个用例只证明一个主要行为。
- 测试必须确定、隔离、可重复并可并行；时间、随机、网络和外部服务通过可控边界注入或显式测试环境管理。
- 既覆盖正常路径，也覆盖边界、拒绝、重复、取消、超时、部分失败和已知反例；高风险不变量可使用属性、模糊或差分测试。
- Mock 只替代明确端口，不能用 Mock 证明数据库约束、序列化、浏览器行为、队列语义或第三方协议兼容。
- 覆盖率用于发现盲区，不作为完成目标；不得编写无断言或只验证实现细节的测试来提高数字。
- Flaky 测试必须定位竞态、污染或时间依赖，不能简单增加重试后长期忽略。

## 评审与重构

- 评审依次检查目标与范围、正确性、安全与隐私、数据/并发边界、可维护性、性能风险、测试和可运维性。
- 反馈指向具体代码、失败场景和证据，标明阻塞程度；讨论实现而非评价作者，不用个人偏好冒充规则。
- 大改动拆成可独立验证的小提交或阶段；格式化、机械迁移、行为变更和大规模重构尽量分开，降低审查噪声。
- 重构前用现有测试或特征测试锁定行为；每一步保持可构建、可回滚，不在同一改动中偷偷改变业务语义。
- 只有重复代码具有相同语义和变化方向时才抽象；过早抽象、万能基类和兜底 `utils` 会放大耦合。
- 删除死代码、注释掉的实现和过期兼容层前，先检索动态入口、配置、消费者和迁移窗口。

## 文档即代码

- 文档先明确受众、任务和前置条件；命令、路径、版本、输入输出和失败处理必须可执行、可复制或可验证。
- 同一事实只保留一个权威来源，其他位置建立引用；接口、配置、迁移或运行方式变更时同步更新文档。
- 重要文档标明 Owner、适用范围和最后验证条件；长期无人维护且不可验证的文档应修正或删除。
- 示例使用虚构、脱敏数据，不包含真实域名凭据、个人信息或不可安全执行的破坏性命令。
- 架构图、流程图和 Runbook 必须对应当前实现；自动检查链接、示例、Schema 或生成内容，减少文档漂移。

## 依赖、许可证与供应链

- 引入依赖前确认需求、维护状态、发布来源、许可证、体积/运行成本、安全记录和替代方案；小功能优先现有能力。
- 依赖版本和锁文件必须进入评审；CI 使用冻结锁文件和可信 Registry，不允许安装脚本无审查执行高权限操作。
- 发布产物应可追踪源码提交、依赖锁和构建环境；关键镜像、二进制或模型保存摘要并进行漏洞/秘密扫描。
- 复制代码、字体、图片、模型、数据集或示例时记录来源和许可证，遵守署名、再分发和商用限制。
- 安全更新先评估受影响路径并验证兼容；不得仅为消除扫描告警盲目升级整个依赖树或关闭检查。
