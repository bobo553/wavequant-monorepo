# 持续交付与发布专项规范

本文件用于 CI/CD、构建产物、环境晋级、灰度、数据库发布和回滚。具体应用的 lint、测试和构建命令仍以工作区规则为准。

## CI 与产物

- CI 使用固定运行时、冻结锁文件和最小权限身份，从干净检出执行；不得依赖开发机全局包、未声明环境或可变缓存才成功。
- 流水线先做格式、静态检查和快速测试，再执行高成本构建、集成和安全扫描；失败立即停止且保留可定位证据。
- 缓存键包含锁文件、工具链、平台和关键配置；缓存是优化而非事实来源，禁用缓存时仍应得到同一结果。
- 构建一次并逐环境晋级同一不可变产物；产物关联提交、依赖锁、构建器、测试结果和镜像/文件摘要。
- CI 凭据使用短期、按环境隔离的身份；来自 Fork、第三方 Action 或不可信脚本的任务不得自动获得生产秘密。

## 发布设计

- 发布计划列出影响面、Owner、依赖、兼容窗口、健康信号、停止条件、回滚/前滚路径和沟通渠道。
- 滚动、蓝绿或金丝雀策略由状态、容量和风险选择；发布期间同时观察技术 SLI 与关键业务护栏。
- 自动回滚只针对可信、可判定且回滚安全的信号；数据已产生不可逆变化时优先止损和前滚修复。
- Feature Flag 有 Owner、默认值、权限、审计、到期和删除计划；不能成为永久分支或绕过代码评审的配置入口。
- 紧急变更可以缩短流程但不能跳过授权、记录、最小验证和事后补审。

## 数据库与兼容发布

- Schema 采用 expand/migrate/contract：先添加兼容能力，再迁移/回填并观测，最后在消费者完成切换后删除旧结构。
- 应用发布与迁移分别可重试、可观测；大表迁移评估锁、事务日志、复制延迟、磁盘和回滚时间。
- 双写必须定义权威来源、失败处理、对账和退出条件；不能把无限期双写当成迁移完成。
- 回填有界限速、检查点、幂等、暂停和恢复能力，不能与在线流量争抢到破坏 SLO。
- 回滚前确认旧版本能读取新数据；不可逆迁移需要备份、恢复演练或明确的前滚方案。

## 验证与审计

- 非生产环境演练部署、回滚、探针、配置、迁移和告警；生产差异必须显式列出并另行验证。
- 发布记录包含操作者/流水线身份、产物摘要、配置/迁移版本、开始结束时间、指标和决策。
- 发布后在约定观察窗口确认错误、延迟、饱和、业务指标和数据质量，再结束变更窗口。
- 失败发布进入复盘和改进清单；不得通过关闭测试、探针或告警来制造“发布成功”。
