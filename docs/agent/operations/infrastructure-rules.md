# 基础设施与云资源专项规范

本文件用于容器、Kubernetes、IaC、IAM、网络、负载均衡、DNS/TLS、CDN 和对象存储边界。生产变更必须先获得根规则要求的授权。

## 容器与编排

- 镜像使用多阶段构建、固定版本或摘要和最小运行时内容；构建上下文排除秘密、源码缓存和无关产物。
- 进程以非 root、最小 Linux capabilities 和尽可能只读文件系统运行；临时写目录显式挂载并设置容量边界。
- 镜像不内置环境秘密，同一镜像跨环境使用；启动脚本正确转发信号并保证日志写标准输出。
- 只有调度、弹性、故障隔离或平台一致性收益超过运维成本时才采用 Kubernetes；小规模服务可以使用更简单的容器平台。
- Kubernetes 工作负载定义 requests/limits、startup/readiness/liveness、优雅退出、滚动策略和安全上下文；副本拓扑、PDB 和自动扩缩容由 SLO 与容量证据驱动。

## IaC 与变更管理

- 云资源、网络、权限和告警以 IaC 为事实来源；紧急控制台修改必须记录并尽快回写，避免长期漂移。
- Plan 与 Apply 分权，生产 Apply 需要评审、授权和受控身份；高风险替换、删除或网络变更单独突出。
- State 使用加密远端存储、版本、锁和最小权限，按敏感数据保护；环境/账号之间隔离状态和凭据。
- 模块输入输出保持窄且版本化，不在模块中隐藏跨环境副作用；Provider 和 Module 升级先查看计划并在低风险环境验证。
- 定期检测 Drift、过期资源、未加标签资产和策略偏差；不得自动删除无法确认所有者的数据资源。

## 身份与秘密

- 人员通过 SSO、MFA、组和角色访问，Root/Owner 账号只作受控 Break-glass；禁止共享账号和永久管理员权限。
- 工作负载与 CI 使用短期角色、工作负载身份或 OIDC，避免长期 Access Key；凭据按环境、服务和用途隔离。
- IAM 策略限制 Action、Resource 和 Condition，定期审查未使用权限、闲置账号和异常调用；发现泄漏立即吊销、轮换并审计影响。
- 秘密在专用管理系统中生成、轮换和注入，不进入 Git、镜像层、日志、Plan、State 或命令历史。

## 网络、DNS 与边缘

- API Gateway/负载均衡统一 TLS、路由、大小限制和粗粒度限流，但领域鉴权和业务权限仍由服务端执行。
- 明确连接、请求、空闲和上游超时；只信任来自受控代理的 Forwarded Header，防止伪造客户端 IP、协议或 Host。
- DNS 变更前核对记录、TTL、证书和回滚；证书自动签发/续期并监控到期，源站到边缘同样使用有效 TLS。
- HSTS、强制 HTTPS 和证书固定等难回滚策略先验证所有子域和恢复路径，不能为“更安全”直接全量开启。
- CDN Cache Key、TTL 和失效策略按内容身份设计；凭据和个人化维度不得进入共享缓存，私有数据默认 `no-store` 或使用隔离缓存。
- 带指纹静态资源可长期不可变缓存，HTML/配置使用短缓存和再验证；发布需支持 Purge/版本回退并防止绕过 CDN 直连源站。

## 验证要求

- 验证镜像扫描、非 root、只读/写目录、信号、资源限制和探针；编排故障测试覆盖重启、驱逐和节点/区域失效。
- IaC 运行格式、校验、计划、策略和 Drift 检查；网络变更验证解析、路由、TLS、回源、缓存隔离和回滚。
- 定期执行权限复核、秘密轮换和 Break-glass 演练，并保存执行证据而非只保留文档。
