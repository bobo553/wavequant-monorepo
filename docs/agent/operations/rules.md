# 运维与交付规范

本文件仅在任务涉及 CI/CD、容器、IaC、环境配置、探针、可观测、发布、扩缩容、备份或灾难恢复时加载。

## 读取路由

| 任务类型                                         | 额外读取文件                                            |
| ------------------------------------------------ | ------------------------------------------------------- |
| 环境、配置、探针、备份和运维基础门禁             | 本文件                                                  |
| CI/CD、构建产物、发布、回滚和数据库发布          | `docs/agent/operations/delivery-rules.md`               |
| 容器、Kubernetes、IaC、IAM、网络、DNS/TLS 或 CDN | `docs/agent/operations/infrastructure-rules.md`         |

只加载当前变更涉及的专项文件；生产操作仍必须满足根规则的授权门禁。

## 环境与配置

- 开发、测试、预发布和生产使用同一构建产物与配置结构，只改变环境值；禁止为环境复制业务代码。
- 环境变量和配置由强类型 Schema 校验，缺少必需值时快速失败；秘密只从环境或秘密管理系统注入。
- 配置变更与代码一样评审、版本化、可回滚并记录影响；高风险动态配置需要权限、审计和灰度。
- 不在日志、CI 输出、镜像层、IaC 计划或状态中公开密钥和真实环境文件。

## CI/CD 与发布

- CI 从干净检出执行锁文件安装、格式、静态检查、测试、构建和必要安全扫描；不能依赖开发机缓存才通过。
- 同一不可变产物逐级晋级，记录源码提交、依赖锁、构建时间和镜像摘要，避免在生产环境重新构建。
- 发布前验证数据库兼容、探针、资源限额、旧消费者和回滚/前滚路径；Schema 破坏性变更采用分阶段迁移。
- 优先滚动、蓝绿或金丝雀发布，设置基于错误率、延迟和业务指标的停止/回滚条件。
- 生产部署、扩容、回滚、基础设施 Apply 和数据恢复必须满足根规则的用户授权与审计门禁。

## 容器与 IaC

- 使用多阶段构建和固定基础镜像版本，运行阶段只包含所需产物；以非 root 用户运行并尽可能使用只读文件系统。
- 容器不保存业务状态，日志写标准输出，临时文件进入受控目录；持久数据使用数据库或对象存储。
- 正确传递 PID 1 信号，不使用会吞信号的启动包装；设置 CPU/内存请求、限制和临时存储边界。
- Compose、云资源和部署配置作为代码进入版本控制、评审和自动校验；执行前查看变更计划，禁止控制台手工状态成为唯一事实来源。
- IaC 状态使用受保护的远端存储、锁、加密和最小权限；状态/计划按敏感信息处理。

## 可观测性

- 日志使用结构化字段，包含时间、级别、服务、版本、环境、request/trace ID、事件名和安全业务标识。
- 一次错误只由拥有处理决策的边界记录；日志、指标和 Trace 不包含 Token、完整身份标识、Webhook/计费 Payload 或个人敏感信息。
- 指标覆盖请求量、错误率、延迟分布和资源饱和度；队列增加积压/最老消息，缓存增加命中/淘汰，数据库增加连接/锁等待。
- 跨服务请求和消息传播 trace、correlation 和 causation 标识；高基数用户/订单 ID 不进入指标 Label。
- 告警绑定用户影响和可行动阈值，并关联 Owner、Runbook、Dashboard 和升级路径；没有处置动作的告警应删除或调整。

## 健康检查与停机

- Liveness 只判断进程是否需要重启，不访问数据库或外部服务；Readiness 判断是否可以接流量并检查关键依赖与初始化。
- 探针快速、有超时且不泄露内部地址或凭据；关键依赖未就绪时返回失败，不能假装 ready。
- 收到终止信号后先标记 not-ready，再停止接收新请求，等待在途事务到限时，最后关闭连接池与进程。
- Worker 停止拉取新任务，完成或安全放回在途消息后退出；启动/停机需测试重复信号、卡住依赖和超时强退。

## 备份、恢复与容量

- 为数据库、对象和关键配置定义 RPO/RTO、备份频率、保留期、加密、跨故障域和恢复负责人。
- 备份成功不等于可恢复；定期在隔离环境执行恢复演练并记录耗时、完整性和缺失步骤。
- 容量规划使用真实吞吐、P95/P99、并发、增长、峰谷和依赖配额，保留安全余量并设置饱和告警。
- 降级、限流和灾备切换必须演练；文档中明确功能损失、数据一致性和恢复条件。

## 验证要求

- 校验 CI 配置、Compose/IaC 语法、镜像构建、秘密扫描、探针、SIGTERM 和标准初始化。
- 发布流程至少在非生产环境验证部署、回滚/前滚、迁移兼容、告警和 Dashboard。
- 注入依赖不可用、资源耗尽、进程重启和区域故障，确认 Runbook 与恢复证据真实可用。
