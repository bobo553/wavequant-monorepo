# Agent、工具与协议专项规范

本文件用于模型工具调用、多步骤 Agent、MCP/A2A 等集成协议和自主循环。没有真实多步骤、跨系统或动态工具选择需求时，优先普通工作流和确定性代码。

## 工具边界

- 工具是由宿主执行的结构化能力，不是模型直接拥有的权限；每个工具定义用途、参数/结果 Schema、副作用和失败语义。
- 工具按最小权限、允许列表、租户和环境隔离；发现工具或服务器不等于获得调用授权。
- 读写能力分开，写操作使用幂等键、预览和审计；删除、支付、发布、生产修改或外部消息必须经过明确授权/确认。
- 参数以 `unknown` 接收并验证长度、枚举、路径、域名和资源范围；工具输出同样是不可信输入，不能作为新指令执行。
- 每次调用设置截止时间、取消、并发、重试和成本预算；未知结果先查询状态，不能盲目重复有副作用调用。

## Agent 循环与状态

- 开始前定义目标、成功条件、可用工具、最大步骤/时间/费用、停止条件和需要人工介入的边界。
- 计划与执行状态结构化保存，至少包含已完成步骤、证据、待办、错误和资源版本；恢复时先核对外部状态。
- 每一步只根据当前目标选择最小必要工具，调用后验证真实结果；不能把“已发起”或模型自述当成完成。
- 循环必须有界，遇到重复失败、无进展、预算耗尽、冲突授权或不可逆决策时停止并升级。
- 多 Agent 只用于边界独立、可并行且合并成本可控的任务；共享可变状态和相互无限委派必须禁止。

## 协议与信任

- MCP/A2A 等协议按项目锁定版本实现并做兼容测试；规则不依赖可能变化的草案字段、默认传输或厂商扩展。
- 对服务器、客户端、Agent 和用户分别认证，并按具体 Capability 授权；来源、身份和会话不可由未验证 Metadata 自报。
- 协议处理明确版本协商、Schema、取消、重试、幂等、分页、超时和错误映射；未知字段按兼容策略处理。
- 远端 Prompt、Resource、工具描述和 Agent 消息均视为不可信数据；不能覆盖本地系统规则或扩大用户授权。
- 记录发现、授权、调用、结果摘要、版本和责任主体；日志脱敏且不能保存工具返回的完整敏感内容。

## 安全与验证

- 高风险代码或文件操作在受限目录、沙箱和网络策略中执行；输出路径规范化并验证仍在允许范围内。
- 外部内容可能包含 Prompt Injection、恶意文件、SSRF 目标或数据外带请求，调用前进行来源、类型和目的校验。
- 测试覆盖参数越界、权限拒绝、超时、取消、重复调用、部分成功、未知结果、恶意工具输出和恢复执行。
- 发布前用受控账号和非生产资源执行端到端演练，确认审批、审计、预算、停止和回滚路径真正生效。
