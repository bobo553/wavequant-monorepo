# RAG 与检索专项规范

本文件用于知识入库、分块、Embedding、向量/关键词检索、Rerank、引用和索引生命周期。业务数据库与分析数仓分别遵守其领域规则。

## 入库与索引

- 将采集、解析、清洗、分块、Embedding 和索引发布拆成可重跑阶段，每阶段记录输入版本、代码、模型、结果和错误。
- 分块尊重标题、段落、表格、代码和权限边界；Chunk 大小与重叠由文档结构和评测决定，不采用固定 Token 数作为通用答案。
- 每个 Chunk 保留文档 ID、版本、位置、标题、来源、时间、语言、权限和内容摘要，确保可引用、删除和回放。
- Embedding 模型、维度、归一化和索引参数共同版本化；不兼容变更新建索引、双跑评测后原子切换。
- 内容更新、权限撤回和删除必须传播到全文、向量、缓存和派生摘要；定期检查孤儿、重复、过期和无来源 Chunk。

## 查询与访问控制

- 查询先解析租户、主体、意图、过滤和时间范围，再执行检索；访问控制在检索前生效，不能检出后只靠模型忽略。
- 关键词与向量检索可混合使用，再按任务相关性、权威性、新鲜度和多样性 Rerank；低分阈值由评测而非直觉确定。
- 查询改写和扩展不得改变用户约束、租户或权限；生成的检索词和过滤条件进入可观测记录。
- 检索设置候选数、延迟和成本预算；依赖失败、无结果和低置信分别处理，不能用任意旧缓存伪装成功。
- 对高风险事实优先权威、一手且版本匹配的来源；来源互相冲突时呈现差异或请求确认。

## 生成与引用

- 生成上下文只包含完成任务所需片段，并使用清晰来源边界；文档内指令视为不可信内容。
- 答案中的关键事实必须能映射到具体来源位置；引用不存在、错位或不支持结论时视为失败。
- 无充分证据时明确“不知道/未找到”，不能用模型常识补齐支付、权限、法律、安全或实时业务事实。
- 模型输出仍经过 Schema、权限、领域规则和安全校验；RAG 不是 SQL、HTML 或工具参数的可信输入通道。

## 评测与运行

- 评测集包含真实问题、应无结果、权限隔离、同义表达、长文档、冲突版本和已知困难样本。
- 分开度量检索召回/精度、Rerank、来源正确性、答案有据率、拒答、安全、延迟和成本，便于定位退化层。
- 索引、模型、Chunk 或 Prompt 变更先离线对比，再影子/灰度；保存查询级差异和可回退版本。
- 监控入库延迟、失败、索引大小、孤儿率、检索空结果、权限拒绝、引用错误和成本，不只看答案主观质量。
