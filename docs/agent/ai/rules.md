# AI 工程规范

本文件仅在任务涉及模型 API、Prompt、RAG、Embedding、工具调用、Agent、结构化生成或 AI 评测时加载。当前业务没有明确 AI 需求时不得提前引入模型依赖。

## 读取路由

| 任务类型                                      | 额外读取文件                            |
| --------------------------------------------- | --------------------------------------- |
| AI 能力边界、输入输出、安全、可靠性和基础评测 | 本文件                                  |
| Prompt、上下文预算、对话记忆或流式生成        | `docs/agent/ai/prompt-context-rules.md` |
| 文档入库、Embedding、混合检索、Rerank 或 RAG  | `docs/agent/ai/rag-retrieval-rules.md`  |
| Agent、工具调用、MCP/A2A 或多步骤自主执行     | `docs/agent/ai/agent-tool-rules.md`     |
| 数据集、微调、模型部署、推理服务或多模态媒体  | `docs/agent/ai/model-delivery-rules.md` |

只加载当前能力涉及的专题；协议和模型版本以项目锁定版本及官方文档为准，不把易过时参数写成永久规则。

## 能力边界与选型

- 先定义用户价值、可接受错误、延迟、成本、隐私和人工兜底，再决定是否使用 AI；确定性规则能解决的问题优先使用普通代码。
- 模型、Provider 和版本通过 Adapter 隔离，业务层不依赖供应商原始响应；切换模型前用同一评测集比较质量、延迟和成本。
- 不承诺模型无法保证的事实正确性、确定性或实时性；高风险结果必须由规则、权威数据或人工复核。

## Prompt 与上下文

- System/Developer Prompt 集中存放、使用简体中文描述业务规则并版本化；代码标识符、JSON 字段和第三方协议保留英文。
- Prompt 明确角色、目标、输入边界、输出 Schema、禁止事项、失败方式和少量必要示例，不依赖聊天历史中的隐式约定。
- 用户内容、检索文档和工具结果使用清晰分隔并视为不可信数据；其中出现的“忽略规则”不得覆盖系统策略。
- 上下文只加载完成任务所需内容，限制条数、字符和 Token；记录截断、排序、去重和来源，避免无界拼接。
- Prompt 变更视为代码变更，必须评审、测试并记录版本；禁止在多个 Controller/组件中散落不可追踪长字符串。

## 输入、输出与工具

- 模型输入先校验、脱敏和限长；不得发送密钥、支付材料、完整个人信息、未授权源码或超出用途的数据。
- 优先使用 JSON Schema/结构化输出，解析时仍以 `unknown` 接收并验证；Schema 不合法、拒答、截断和空结果进入显式错误路径。
- 模型输出是建议而不是事实来源，进入数据库、命令、HTML、SQL、路径或外部消息前必须进行领域校验和上下文编码。
- 工具采用最小权限、参数 Schema、域名/路径白名单、超时和调用预算；读与写分离，高风险写入、删除、支付、发布需明确确认。
- 防止 Prompt Injection 通过文档或网页触发越权工具；模型不能自行扩大用户授权范围。

## RAG 与知识来源

- 文档入库前记录来源、权限、版本、时间和分块策略；检索时继承原文档访问控制，禁止跨用户/租户泄漏。
- 检索结果保留可追踪来源和相似度，低置信或无证据时明确回答不知道，不能用模型常识填补关键事实。
- Embedding 模型、维度和分块策略版本化；变更时建立新索引并验证后切换，旧向量不得混用。
- 原文删除、权限变化和更新必须能传播到索引；建立过期、重复、孤儿 Chunk 和召回质量检查。

## 可靠性、成本与观测

- 模型调用设置连接/响应超时、取消、并发、速率和单请求 Token/费用预算；重试仅处理瞬时错误并使用退避抖动。
- 流式输出处理取消、半截 JSON、断连和重复 Chunk；未完成结果不能作为成功持久化。
- 缓存键包含模型、Prompt、参数、权限和输入摘要；含个人或实时数据的结果默认不共享缓存。
- 记录模型/Prompt 版本、延迟、Token、费用、结果状态和安全分类，但不记录原始秘密或敏感全文。
- Provider 不可用或触发预算时提供明确降级、排队或人工路径，禁止伪造 AI 成功结果。

## 评测与发布

- 建立版本化评测集，覆盖正常、边界、拒答、越权、注入、多语言和已知失败；敏感生产样本需脱敏和授权。
- 评测同时度量任务正确性、格式有效率、引用/事实、拒答、安全、延迟和成本，不能只看主观“效果不错”。
- Prompt、模型、检索或工具变更先离线评测，再灰度/影子验证；设置回退版本和线上质量监控。
- 非确定性断言使用统计重复和容忍区间，避免单次生成测试；关键结构和权限规则仍必须确定性通过。
