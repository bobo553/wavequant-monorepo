# Prompt 与上下文工程专项规范

本文件用于 System/Developer Prompt、上下文组装、对话记忆、流式响应和 Prompt 版本治理。模型输出的领域校验仍遵守 `docs/agent/ai/rules.md`。

## Prompt 结构

- Prompt 按任务、输入、约束、输出和失败方式组织；规则使用肯定、可执行语言，并明确优先级和冲突处理。
- 不可信用户内容、检索文档和工具结果使用稳定分隔符包裹，只作为数据；其中出现的指令不得改变系统权限和目标。
- 示例必须与规则和 Schema 一致，覆盖最容易误解的边界；过多示例会挤占真实上下文并诱导机械模仿。
- 信息不足且会显著改变结果时请求澄清；可安全假设时声明假设并继续，不能用编造内容填补关键缺口。
- 不依赖不可审计的“思维过程”保证正确性；使用结构化中间状态、检查清单、工具证据和确定性验证器。

## 上下文组装与预算

- 将上下文分为固定任务/不变量、最近交互、检索事实和工作状态，分别设置数量、字符或 Token 预算。
- 稳定、可缓存的规则放在前部，用户输入和实时检索放在后部；不能为缓存命中牺牲规则优先级或数据隔离。
- 选择上下文依据相关性、新鲜度、权限和来源可信度，不按先进先出无界追加历史。
- 截断、摘要、去重和排序必须可观察；被省略的信息可能影响答案时应显式提示或缩小任务。
- 摘要保留决策、约束、未完成项和来源指针，并记录版本；摘要不能升级为比原文更高权威的事实。
- 长任务把可恢复状态持久化为显式计划、产物和验证证据，不能把聊天窗口当成唯一内存。

## 记忆与隐私

- 记忆分为会话工作状态、用户偏好和长期业务事实；每类定义用途、写入条件、保留、修改和删除方式。
- 只有获得授权且未来确有用途的信息进入长期记忆；敏感、一次性和推测内容默认不持久化。
- 检索记忆前执行租户/用户隔离，输出时避免泄露记忆存在性、其他主体信息或已撤回内容。
- 记忆冲突时保留来源和时间，以权威业务数据或用户最新明确指令为准，不静默合并矛盾事实。

## 流式与版本验证

- 流式协议定义开始、增量、工具调用、完成、错误、取消和重连事件；客户端不得把半截内容当作最终结果。
- 取消必须传播到模型、检索和工具；断连后是否恢复、重试或重新生成要有明确语义，避免重复写入。
- Prompt 以独立版本管理，变更记录目的、适用模型、输入 Schema 和评测结果；禁止散落复制后各自漂移。
- 测试覆盖正常、边界、冲突、注入、超长、空输入、拒答、结构错误和多语言；发布同时观察质量、延迟和成本回归。
