# 前端工程规范

本文件保存 Web、React Native、移动 H5 和浏览器扩展 UI 的前端规则，是 `docs/agent/frontend` 分类入口。所有前端任务先读取“基础规范”，再按下表只加载与当前任务匹配的专项章节，避免把整份文档无差别放入上下文。

## 基础规范

### 类型与数据边界

- 继承根规则的 TypeScript 严格模式。Props、Hook 参数、事件回调和公开 API 必须有可检查类型；简单局部值依赖可靠推断，不重复标注明显类型。
- Props 使用 `type` 或 `interface` 标注函数参数，不强制 `React.FC`；只读集合和不可修改字段使用 `readonly`。`prop-types` 仅用于暂时无法迁移的 JavaScript 组件。
- API、URL、Storage、跨窗口消息、用户输入和第三方 SDK 返回值先以 `unknown` 接收，再通过 `@repo/contracts`、Zod 或类型守卫校验。
- 仅当空值是合法状态时使用 `?.`；空值默认使用 `??`，只有全部 falsy 值都应回退时才使用 `||`。必填数据缺失必须显式失败，不能用可选链掩盖。
- Props、State、Context、查询缓存和入参均视为只读快照；禁止原地修改，并注意展开运算符只产生浅拷贝。

### React、状态与副作用

- 组件渲染、Selector、Reducer 和数据转换保持纯净；用户动作放事件处理器，Effect 仅同步外部系统，不用来维护可在渲染期派生的重复状态。
- Effect 或生命周期中创建的监听器、定时器、Observer、动画帧、Worker、请求和订阅必须按所有权清理；请求使用 `AbortSignal` 防止过期响应和卸载后更新。
- 状态选择唯一事实来源：服务端数据进查询缓存，可分享的筛选/分页进 URL，跨会话偏好进持久化存储，局部交互留在组件，跨页面客户端状态才进 Store。
- Storage 数据必须有 Schema、版本、默认值和迁移/失效策略，读取后重新校验；不得存储 Token、密码、支付数据等敏感信息。
- 异步操作必须处理加载、失败、超时、取消和竞态；重复提交提供禁用、去重或幂等保护，不吞异常或伪装成功。

### 组件与模块

- 使用函数组件与 Hooks，只保留必要状态；组件遵守单一职责并优先组合，不为了形式机械增加 Container、HOC 或全局状态。
- 组件符号使用 PascalCase，Hook 使用 `useXxx`，内部处理器使用 `handleXxx`，对外事件 Props 使用 `onXxx`。
- 一个实现文件只公开一个主组件；紧密耦合的私有子组件或复合组件可以同文件存在，但达到规模阈值仍须拆分。禁止 React Mixins。
- 复用逻辑优先使用普通函数、组合和自定义 Hook。相似代码确认语义与变化方向一致后再抽象，不能把无关函数堆进通用 `utils.ts`。
- `index.ts` 只暴露稳定公共 API。Web 组件目录按本文件专项规范提供入口，其他内部目录不机械创建 Barrel，避免循环依赖和意外扩大 API。

### 代码卫生、样式与安全

- 默认使用 `const`，需要重新赋值时使用 `let`，禁止 `var`。箭头函数用于短回调或词法 `this`，具名函数用于公共逻辑、递归和清晰堆栈，不做机械转换。
- 生产代码不得保留临时 Console、Debugger、注释掉的实现或无责任人的 TODO。诊断使用统一日志/遥测并脱敏，注释只解释原因、边界和取舍。
- 静态样式使用 Tailwind CSS、CSS Modules、NativeWind 或集中式 `StyleSheet`；只有运行时坐标、动画值和动态 CSS 变量允许内联。颜色、间距、圆角和阴影使用设计令牌。
- Web 使用 `border-box`、Flexbox/Grid 和响应式约束，避免绝对坐标拼页面、高特异性选择器、无边界 `!important` 与 `transition: all`。
- 优先语义化 HTML 和原生交互。可操作元素必须支持键盘、可见焦点和正确标签；图片提供合适 `alt`，图标按钮提供可访问名称，ARIA 不替代原生语义和焦点管理。
- 不可信 HTML、链接、上传文件和跨上下文消息必须校验；任意 HTML 只有经过评审的清洗方案后才能渲染。错误界面不得泄露堆栈、内部路径和服务端原始异常。

### 数据访问与基础验证

- API Client 统一管理 base URL、认证 Header、取消、重试和错误映射；Fetch 必须检查 `response.ok` 或状态码，因为 4xx/5xx 不会自动 reject。
- Store 只保存最小规范化状态，派生值由纯 Selector 计算；组件细粒度订阅所需字段，避免读取整个 Store 造成无关渲染。
- 页面和关键组件必须处理加载、空数据、错误、无权限、禁用、重复提交、长文本和窄屏，路由或高风险功能提供可恢复错误边界。
- 测试面向用户行为与公开 API；缺陷修复补回归测试。UI 改动还须在真实浏览器或设备验证 Console、Network、布局、键盘和焦点。

## 路由、导航与 URL 状态

- URL 是导航契约：资源标识放路径参数，可分享的筛选、排序、分页和搜索放查询参数；使用前完成解码、Schema 校验、默认值和非法值回退。
- 应用内导航使用框架 `Link` 和 Router API，保留新标签页、复制链接、前进后退和中键点击；不得用普通点击处理器模拟链接。
- 页面、功能或重量级依赖按实际访问边界分包；懒加载提供加载、失败和重试状态，不能为了拆包制造大量细碎请求。
- 验证深层 URL 直达、刷新、404、登录回跳和浏览器历史；导航后按产品语义恢复滚动并管理焦点。
- 客户端路由守卫只负责交互引导，服务端仍须执行身份认证与资源授权。
- SSR/SSG/CSR 按 SEO、个性化、更新频率、缓存和运行成本选择；Next.js 优先在服务端获取可缓存数据，不把无交互页面整体客户端化。

## 国际化与内容适配

- 支持多语言的 workspace 使用稳定语义 Key、命名空间、默认语言和缺失翻译回退，不在业务组件散落用户可见硬编码文案。
- 日期、时间、数字、货币、百分比、列表和复数使用 `Intl` 或统一 i18n 能力；领域层保存原始值、时区和币种，不保存本地化字符串。
- Web 根节点同步 `lang` 与 `dir`；RTL 使用逻辑属性和 `start`/`end` 语义，不复制两套布局。
- 布局须容纳语言膨胀、长单词、多行文案和字体差异；关键页面验证默认语言、最长文案语言及产品支持的 RTL。
- 翻译使用带命名参数的完整消息模板，不拼接语序；富文本翻译使用受控组件插槽，禁止注入任意 HTML。

## 实时通信与后台活动

- 低频查询使用带退避的 Polling，单向文本流优先 SSE，高频双向或二进制通信才使用 WebSocket；按方向、频率、延迟和基础设施选型。
- 显式建模连接、重连、关闭和错误状态；处理心跳/超时、离线、页面可见性、指数退避与随机抖动，禁止无上限立即重连。
- 消息按不可信输入处理并使用版本化契约校验；需要一致性时定义消息 ID、顺序、去重、幂等和断线续传。
- 认证使用短期凭据或受保护 Cookie，不在 URL、日志和产物暴露长期令牌；重连前检查凭据刷新。
- 组件卸载时取消自身订阅，共享连接由上层所有者关闭；高频流设置批处理、采样、丢弃或背压策略。

## 性能、图形与构建产物

- 先测量后优化。根据目标设备和网络定义 LCP、INP、CLS、首屏 JavaScript 与关键路由 Chunk 预算；实验室数据用于回归，真实用户数据用于线上趋势。
- 大列表、图表、图片和路由按瓶颈采用虚拟化、懒加载、代码分割或服务端渲染；依赖按需导入并检查 tree-shaking，重量级依赖须比较包体积和替代方案。
- 图片使用合适格式和实际尺寸，并提供 `width`/`height` 或稳定宽高比；非首屏图片可懒加载，LCP 候选资源不得机械懒加载。
- DOM 几何读取与样式写入分批执行；动画循环使用 `requestAnimationFrame` 并清理。`transform`、`opacity`、`will-change` 和合成层优化都必须通过 Performance 记录验证。
- 高频事件按交互语义使用节流、防抖或动画帧调度；超过帧预算的 CPU 任务拆分、延后或移入 Web Worker，并支持取消与错误回传。
- Canvas 用于大量像素级动态绘制，SVG 用于需清晰缩放、DOM 交互和可访问性的矢量内容；Canvas 处理设备像素比、尺寸变化、暂停恢复、销毁和文本备选。
- 动画尊重 `prefers-reduced-motion`，关键操作不能只靠动画表达；自动播放、循环和大面积动效提供暂停或降级。
- 生产静态资源使用内容 Hash 与长期不可变缓存，HTML/入口清单采用可及时更新策略；Source Map 仅按调试或错误追踪需要生成，并控制公开源码风险。
- 性能优化记录前后证据；路由、i18n、实时连接和持久化变更分别验证历史导航、语言/RTL、断线重连与数据迁移回退。

## 异步视图与弹框体验

本节适用于 Web React。弹框外观、焦点、键盘交互与遮罩优先复用 `@repo/design-system-web` 原语；异步加载和调度留在消费应用，除非已经形成多个真实消费者且 API 稳定。

- 图表、编辑器、预览器、导入导出和复杂向导等低频重型视图可使用 `next/dynamic` 或动态 `import()`；高频、轻量和首屏关键反馈直接同步渲染。
- 懒加载提供尺寸稳定、可访问的 loading、error 与 retry 状态；加载失败、取消或卸载都不得被调用方当作成功。
- 用户通过焦点、指针或触摸表达打开意图时可以预加载，但不能只支持 hover，也不能让预加载抢占 LCP 和当前用户操作。
- 多来源互斥弹框需要单一宿主和显式队列，定义优先级、同级 FIFO、取消、账号/路由切换清理与关闭结果；不允许靠多个全局 Provider 竞争焦点。
- 同时可见的非互斥浮层必须先定义层级、焦点、Escape、遮罩和关闭顺序；关键流程优先使用路由而不是层层弹框。
- 动态 `import()` 发出后通常无法中止；关联数据请求仍须独立使用 `AbortSignal`，渲染异常由 Error Boundary 处理。
- 用 Next.js 生产构建和包分析验证重型模块未进入不需要它的首屏 Chunk；预算来自真实产物，不依赖某个未安装的专用插件。
- 真实浏览器验证首次/预加载打开时延、Console、Network、焦点回归、键盘、Escape、遮罩、窄屏和重复触发。

## Web React 组件规范

本节适用于 PC Web、移动 H5 与使用 React 的浏览器扩展 UI。React Native 不引入 shadcn/ui。新组件立即执行；实质修改旧组件时同步迁移本次触及部分。

### 文件规模与拆分

- `.tsx` 实现文件以 350 行为正常上限，351～400 行仅允许作为有理由的临时迁移区间，400 行为硬上限。
- 达到阈值时按视图、状态逻辑、数据适配、类型和工具拆分；不能压缩格式、删除必要注释或堆叠表达式规避行数。
- 每个实现文件只公开一个主组件；紧密耦合的私有子组件或复合组件可以同文件存在，但不能绕过拆分要求。

### 分类、命名与入口

- 组件按 `ui`、`form`、`data-display`、`feedback`、`navigation`、`layout` 等职责分类，不能全部堆在无含义的 `components` 根目录。
- 设计系统原语进入 `packages/design-system/web/src/components/<type>/<component-name>/`；应用共享组件进入 `src/shared/components/...`；业务组件进入 `src/features/<feature>/components/...`。
- 复用顺序为设计系统原语、应用共享组件、功能组件；含接口、权限、路由或领域流程的组件不得进入设计系统。
- 目录和文件使用 kebab-case，React 符号使用 PascalCase；文件名与主导出语义一致。
- 每个组件目录以 `index.ts` 作为唯一公开入口，导出稳定组件和类型；禁止跨模块深层导入实现文件。

推荐结构：

```text
<type>/<component-name>/
├── <component-name>.tsx
├── <component-name>.types.ts
├── <component-name>.test.tsx
└── index.ts
```

### 中文注释与 shadcn/ui

- 每个导出组件使用简体中文 TSDoc 说明职责、范围和边界；复杂状态、副作用、兼容性、性能和业务约束解释“为什么”，不逐行翻译代码。
- PC Web 使用的 shadcn/ui 原语只在 `packages/design-system/web` 生成、升级和维护，应用不得复制 `components/ui`；Admin 特有的业务组合组件仍留在 Admin 应用。
- 保持 shadcn/ui 的组合 API、可访问性、`className` 扩展、CVA 变体和 `cn` 合并风格，不用业务特例破坏原语。
- 新增或升级原语后更新组件汇总入口、包导出和必要测试，并验证受影响的 Web 消费者。
