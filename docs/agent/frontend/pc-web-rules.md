# PC Web 页面规范

本文件适用于 `apps/webs/admin` 和其他以桌面浏览器为主要载体的页面，包括官网、内容站、用户门户、交易/业务应用、数据工作台与 Admin。H5 使用前端通用规则并按移动视口验证，不因位于 `apps/webs` 自动套用 PC 布局约束。

## 场景与应用边界

| 场景                    | 默认页面骨架                        | 首要目标                       |
| ----------------------- | ----------------------------------- | ------------------------------ |
| 官网、活动页、内容站    | Header + 主内容 + Footer            | 内容发现、SEO、阅读与转化      |
| 用户门户、交易/业务应用 | Header/轻导航 + 工作区              | 任务完成、状态反馈与流程连续性 |
| 数据工作台、Admin       | Sidebar + Topbar + 高密度内容工作区 | 检索、比较、批处理、审计与效率 |

- 新页面先判断用户、核心任务、信息密度、认证边界和 SEO 需求，再选择页面骨架；禁止因仓库已有 Admin 示例就让官网或普通业务页套用后台侧栏。
- 同一部署、认证、环境和发布节奏下的不同页面形态优先使用 route group 与嵌套 layout；只有域名、权限信任边界、配置、发布或团队所有权确实独立时才新增 workspace。
- `apps/webs/admin` 是 B 端管理后台示例；`apps/webs/h5` 是面向消费者的移动 Web 起点。复制模板时删除示例领域数据、无关导航和第三方标识，不能把演示内容当作产品契约。
- 所有 PC Web 应用复用 `@repo/design-system-web` 的原语、Token 与可访问性交互；App Shell、导航树、权限、接口和业务组合留在各应用。

## 布局与响应式

- PC-first 表示优先优化键鼠、大视口和多列任务，不表示固定画布。页面使用流式宽度、合理 `max-width`、Grid/Flex 和内容驱动断点，禁止按单一设计稿宽度绝对定位。
- 官网和内容页控制正文阅读宽度，让背景与分区可延伸；工作台和 Admin 可利用更宽空间，但表单、文本与操作区仍需限制行长和扫描距离。
- Sidebar、Topbar、面包屑、页标题和操作区职责唯一；重复导航或同一动作在多个固定区域竞争会降低可预测性。
- 窄屏时按任务优先级重排、折叠或切换导航；除二维表格、时间轴、地图等本质需要二维浏览的内容外，不允许整页横向滚动。
- 支持浏览器缩放、系统字号、长文本、空数据和本地化膨胀；固定高度容器必须说明滚动所有权，避免页面滚动与内部滚动互相争抢。
- Loading、empty、error、forbidden、offline 与 partial-success 状态保持布局稳定，并提供下一步；Skeleton 只模拟真实结构，不用于掩盖无截止时间的等待。

## Next.js 页面与数据

- App Router 的 page/layout 默认保持 Server Component；状态、事件、浏览器 API 或客户端 Hook 只下沉到最小交互叶子，避免整个 App Shell 因一个按钮进入客户端 bundle。
- Server Component 只向 Client Component 传递界面实际使用且可序列化的最小字段，不透传大型 DTO、ORM 对象、秘密或无关属性。
- 页面内相互独立的数据请求并行启动；存在依赖的请求只串行必要部分。慢区域使用有语义的 Suspense/loading 边界，不能让次要卡片阻塞整页首屏。
- 可缓存数据明确缓存键、作用域、失效和权限维度；个性化或授权数据不得进入跨用户缓存。Mutation 完成后只刷新受影响资源。
- 图表、富文本编辑器、地图、代码编辑器和导入导出向导等低频重型功能按访问边界动态加载，并提供尺寸稳定的 loading/error/retry；首屏关键内容不得机械懒加载。
- 可从当前 Props/State 推导的值在渲染期计算，不复制到 State 再用 Effect 同步；筛选、排序、分页和可分享视图优先进入 URL。

## 视觉层级与交互

- 每页明确一个主标题、主要任务和主操作；主按钮不能因多个卡片重复出现而失去层级，次要操作进入就近区域或受控菜单。
- 使用设计 Token 表达颜色、间距、字号、圆角、阴影和层级；业务状态使用稳定语义色并同时提供文本/图标，不只靠颜色传达。
- 表单按任务分组，标签持续可见，校验信息靠近字段并可被辅助技术关联；长流程使用保存草稿、分步或离开保护，而不是无限长弹框。
- Modal/Dialog 只承载短而聚焦的确认或编辑；复杂流程、可分享内容和需要浏览器历史的任务使用独立路由或 Sheet/页面。
- 鼠标 hover 不能是唯一入口；所有操作支持键盘、清晰焦点、合理 Tab 顺序和可访问名称。快捷键不得覆盖浏览器/辅助技术惯例，并提供可发现提示。

## Admin 与高密度页面专项

- 权限必须在服务端/API 强制执行；前端隐藏按钮只改善体验。页面区分无权限、资源不存在和暂时失败，避免泄露敏感资源是否存在。
- 数据表默认使用语义化 `<table>`。只有需要单元格级键盘导航、编辑或选择的复合控件才采用 ARIA Grid，并完整实现其焦点与键盘模型。
- 表格明确主键、列语义、排序、筛选、分页、空值和时区；列过多时提供列显隐、固定关键列或详情视图，不无限压缩文字。
- 筛选、搜索、排序、分页和视图偏好应可恢复；需要分享或前进后退的状态进入 URL，个人列偏好可进入带版本的本地/服务端设置。
- 批量操作先显示选择范围和影响数量，支持跨页选择时明确“当前页”与“全部结果”；执行后报告成功、失败和可重试项，不能只弹统一成功提示。
- 删除、禁用、退款、权限变更等高风险操作说明对象与影响，按风险使用二次确认、输入确认、幂等键、审计日志或撤销能力。
- Dashboard 指标必须定义口径、单位、时间范围、时区和更新时间；图表提供文字摘要、Tooltip、空/异常状态，不用装饰图形替代可比较数据。
- 高密度不是字号更小。优先通过分组、对齐、渐进披露、快捷操作和用户可选密度提高效率，同时保持可点击目标与可读性。

## 性能与质量门禁

- 每个 workspace 声明主要桌面视口、最窄支持宽度与浏览器范围；至少验证常用桌面宽度、窄屏回退、缩放、长文本和真实数据量，不把单个截图视为响应式证明。
- 使用生产构建检查路由 Chunk、客户端 JavaScript、图片与字体；独立面板避免请求瀑布，长列表/大表格在真实数据量下评估分页、虚拟化或服务端聚合。
- 单元/组件测试覆盖状态和用户行为；Playwright 覆盖导航、深链、刷新、键盘和关键任务。Admin 追加权限拒绝、批量操作、危险确认及部分失败流程。
- UI 验证同时检查 Console、Network、hydration、焦点、布局偏移和错误边界；共享设计系统变更至少验证 `h5` 与 `admin` 两个现有消费者。

pnpm --filter <workspace-name> lint
