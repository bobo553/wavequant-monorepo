# 算法规范

本文件仅在任务涉及非平凡算法、数值计算、搜索/排序策略、随机过程、规则结算或性能敏感数据处理时加载。普通 CRUD 和简单集合转换不需要读取本文件。

## 问题定义

- 编码前明确输入、输出、不变量、合法/非法状态、数据规模、精度、延迟和内存预算。
- 先给出可验证的正确性基线，再优化复杂度；不能用“更快”的复杂实现替代没有测试的正确实现。
- 记录算法适用边界和退化情况，包括空集、单元素、重复值、极值、有序/逆序、稀疏/稠密和恶意输入。
- 复用成熟标准库或项目实现；自研算法需说明现有能力不满足的原因。

## 正确性与确定性

- 关键不变量在类型、断言或测试中表达；错误输入显式拒绝，不能靠零值或截断继续计算。
- 同一输入应产生确定输出；确需随机时注入随机源、记录 Seed，并使测试可复现。
- 排序和选择算法明确稳定性、Tie-breaker 和全序规则；分页、排行榜和奖励结算必须追加唯一键。
- 避免依赖 Map 遍历、并发完成顺序、浮点误差或本地时区产生不确定业务结果。
- 服务端权威算法不能相信客户端累计值、时间、概率、价格或权益结果；客户端只提交可验证输入或事件。

## 数据结构与算法范式

- 先列出占主导的操作及频率，如查找、插入、删除、排序、范围查询、最短路或去重，再选择数据结构；不按熟悉程度套模板。
- 优先使用标准库中语义明确的数组、Map、Set、堆和队列；自定义结构必须证明内存布局、复杂度或领域不变量确有收益。
- 哈希结构要评估冲突、内存和无序性；树/堆要明确平衡、比较器和重复键；图结构要明确有向性、权重和稀疏程度。
- 分治必须定义可缩小的子问题和合并成本；递归终止条件同时进入实现与测试。
- 贪心策略必须说明局部选择为何得到全局正确结果，或提供反例检查；无法证明时不能只凭样例采用。
- 动态规划明确状态、转移、初始值、遍历顺序和空间压缩前提，避免状态遗漏或覆盖尚未使用的值。
- 图搜索维护已访问状态、终止条件和不可达结果；启发式搜索需说明启发函数对完备性和最优性的影响。

## 数值与复杂度

- 金额、货币和账本不用二进制浮点；概率、经验、离线收益和大数运算明确溢出、舍入、上下界与单位。
- 时间复杂度和空间复杂度按最坏情况或明确分布评估，关注隐藏的复制、排序、序列化和网络成本。
- 对输入大小设置硬上限；递归必须证明终止并评估栈深，可能退化时改为迭代或显式栈。
- 大数据处理优先流式、分块和有界内存；禁止为简化实现无界加载或创建平方级中间集合。
- 并行化前确认任务可分割、无共享写冲突且收益覆盖调度开销；并发数量仍遵守后端可靠性规则。

## 业务规则与结算算法

- 计费、评分、配额、概率与权益规则使用版本化配置，并保存计算所需版本以支持审计和重放。
- 时间窗口型结算使用服务端时间、最大有效窗口和明确舍入顺序；重复请求或重试不得重复产生权益。
- 随机结果如需防预测，使用密码学安全随机源；可验证模拟和测试使用可注入 Seed，二者不得混用。
- 排名明确同分规则、周期边界、迟到数据和重算策略；缓存结果不能成为最终结算的唯一依据。

## 测试与基准

- 单元测试覆盖示例、边界、错误和已知反例；适合时加入属性测试、不变量测试、差分测试或模糊测试。
- 优化前保存基线实现并进行结果对比，确保性能改写没有改变语义。
- Benchmark 固定环境、数据分布、预热和迭代方式，同时记录时间、分配、内存和输入规模；单次数字不作为结论。
- 性能回归设置与业务预算相关的阈值，避免对机器噪声敏感的过窄断言。
- 复杂算法的注释解释公式来源、不变量和取舍，不逐行翻译代码；测试用例作为可执行说明。
