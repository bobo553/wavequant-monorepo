# 后端安全与身份规范

本文件仅在任务涉及认证、授权、Token、OAuth/OIDC、Webhook、秘密、计费或敏感输入时加载，并继承 `docs/agent/backend/rules.md`。

## 基础安全原则

- 所有外部请求、消息、Webhook、上传和第三方响应均不可信；先校验身份、完整性、Schema、大小和时效，再进入业务逻辑。
- 默认拒绝访问。每个端点明确是否公开、需要何种身份、权限、资源所有权、租户边界、限流、幂等和审计。
- 认证（AuthN）只回答“是谁”，授权（AuthZ）回答“能做什么”；两者分层执行，不能把“已登录”当作“有权访问该资源”。
- 服务端从可信登录态解析用户、角色、租户和资源范围，不接受客户端覆盖；对象级授权在查询/写入时强制执行。
- 安全失败使用最少信息原则。登录、找回、绑定等接口避免暴露账号是否存在，内部原因通过安全审计定位。

## 会话与 Token

- Web 默认优先使用 `Secure`、`HttpOnly`、合理 `SameSite` 的受保护 Cookie；不要把长期 Token 默认放入 `localStorage`、URL 或可被脚本读取的位置。
- 使用 Cookie 承载认证时，对所有有副作用请求实施 CSRF Token、Origin/Referer 校验或等效防护；`SameSite` 不是唯一防线。
- Access Token 短期有效，Refresh Token 轮换、可撤销且检测重放；注销、密码/权限变更和风险事件必须能使相关会话失效。
- JWT 校验固定算法白名单、签名、issuer、audience、`exp`、`nbf` 和必要的 `jti`；拒绝 `none`、算法混淆和缺失关键 Claim。
- JWT Payload 只放最小授权上下文，不存密码、密钥、完整个人资料或支付数据；签名只防篡改，不提供保密。
- Token、Session ID 和 API Key 不进入 Query、日志、错误、Trace、分析事件或前端持久化快照。
- 服务间认证使用独立短期凭据和最小权限身份，不复用终端用户 Token 或共享万能密钥。

## 密码与账户保护

- 如业务需要密码，使用经过审查的 Argon2id、bcrypt 或 scrypt 库和可升级参数；禁止明文、可逆加密、MD5、SHA-1 或普通快速哈希。
- 每个密码使用随机盐；可选 Pepper 由秘密管理系统保存。算法、参数和迁移版本随哈希记录，登录成功时可渐进升级旧哈希。
- 密码、验证码、重置 Token 和恢复码只在必要时间保留；重置 Token 单次使用、短期有效并以不可逆摘要存储。
- 登录与恢复流程按账号、IP、设备和风险信号限流，使用逐步延迟/挑战；账号锁定要防止攻击者恶意锁死他人账号。
- 敏感账户操作要求重新认证或提升验证，并撤销其他会话、记录审计、通知用户。

## 授权与管理后台

- RBAC 适合稳定角色，ABAC/策略适合资源、租户、组织和环境条件；权限命名使用业务动作，不以页面按钮代替后端权限。
- 管理员、运营、客服和自动化身份使用最小权限；高风险动作可要求双人复核、二次认证或审批，不能只有前端确认框。
- 列表、详情、更新、导出和批量操作都要执行同等对象级授权；禁止只保护详情端点而让搜索/导出泄露数据。
- 权限变更及时使缓存与会话失效。策略决策记录主体、资源、动作和结果，但不记录秘密或完整敏感内容。
- 审计日志追加写、可查询且有保留策略；操作者不能删除或修改自己的高风险操作记录。

## OAuth/OIDC 与第三方身份

- 客户端只提交一次性授权结果；服务端通过官方端点换取身份并校验 issuer、audience、nonce、PKCE、签名和 Provider 响应，绝不下发 Client Secret。
- Authorization code、access token、refresh token 和解密材料不得记录或返回给无权主体；在内存中的生命周期保持最短。
- 第三方身份使用 `provider + providerSubject` 唯一约束，本地用户与外部身份分开建模，不按昵称、头像或邮箱猜测合并。
- OAuth 回调校验一次性 `state`/nonce、精确 redirect URI 和授权发起会话，防止登录 CSRF、Code 重放和开放重定向。
- 账号绑定、解绑和合并属于高风险操作，需要当前会话验证、冲突检查、审计和可恢复流程。
- 第三方 API 超时或结果未知时返回可重试错误，不创建半绑定身份；Provider 错误映射为内部稳定错误码。

## Webhook 与计费 Provider

- Webhook 在解析业务 Payload 前保留原始请求体，按 Provider 协议校验签名、时间戳、事件 ID、来源和重放窗口。
- 回调按 Provider 事件 ID 和业务对象 ID 幂等落库；重复通知返回协议要求的成功响应，但不得重复修改状态或发放权益。
- 客户端提供的金额、套餐、资源归属和状态不作为权威数据；服务端配置和 Provider 权威结果决定最终写入。
- 数据库状态与 Outbox 在同一事务提交；事务成功后再 ACK，需要的后续副作用由幂等消费者完成。
- 外部状态机只允许合法迁移；未知、冲突、撤销和退款等状态不得靠最后写入覆盖。
- 结果未知时使用 Provider 查询或对账接口确认，保留可审计差异；私钥、Webhook Secret 和证书进入秘密管理与轮换。

## 注入、SSRF 与协议安全

- SQL、搜索查询、Shell、模板和日志字段使用参数化/结构化 API；禁止拼接未校验输入。Shell 调用优先参数数组并限制可执行命令。
- 所有服务端 URL 抓取、Webhook 回调和文件导入防 SSRF：限制协议/端口/域名，解析后拦截环回、私网、链路本地和云元数据地址，并控制重定向。
- 输出到 HTML、CSV、日志或 Header 前按目标上下文编码；禁止把通用“过滤”当作跨上下文安全方案。
- CORS、CSP、安全 Header 和 TLS 由入口与应用协同配置；生产环境不得关闭证书校验或暴露调试/Swagger 管理端点给未授权网络。
- 反序列化只接受允许的格式和类型，不执行 Payload 中的类型名、脚本或模板；压缩包限制展开大小、层数和文件数量。

## 上传与隐私

- 上传按 `docs/agent/backend/data-rules.md` 使用私有对象存储；在业务可见前完成类型、魔数、大小、配额和必要的恶意内容扫描。
- 原始文件名只作经过清洗的展示元数据，不参与路径；下载响应安全设置 Content-Type、Content-Disposition 和缓存策略。
- 个人信息遵循最小收集、明确用途、访问控制、保留期限与删除流程；日志、测试数据和分析系统同样适用。
- 标识符展示与日志脱敏，禁止完整输出 Provider Subject、手机号、邮箱、IP、设备标识和计费字段；需要关联时使用稳定不可逆摘要或内部 ID。

## 秘密与供应链

- 秘密只从环境或秘密管理服务注入，仓库仅保留无敏感值的 `.env.example`；启动日志不得打印完整配置对象。
- 凭据按服务和环境隔离并最小授权，支持轮换和撤销；发现泄漏时先吊销再清理 Git 历史，不能只删除文件。
- 新依赖检查维护状态、许可证、权限、传递依赖和已知风险；锁定版本并通过 Dependabot/审计流程更新。
- 镜像和依赖构建可追溯，生产产物不包含测试密钥、源码凭据、包管理缓存或不必要的调试工具。

## 安全验证清单

- 覆盖未认证、权限不足、跨用户/跨租户访问、角色变更、会话撤销、Token 过期/重放和 CSRF。
- 覆盖 SQL/搜索注入、SSRF、超大输入、未知字段、恶意上传、路径穿越和错误信息泄漏。
- Webhook/计费覆盖伪造签名、篡改数据、重复/乱序回调、事务失败、Outbox 重试、重复副作用和对账差异。
- 提交前扫描真实秘密、私钥、证书、Token、环境文件和敏感日志字段；安全失败不得通过关闭校验绕过。
