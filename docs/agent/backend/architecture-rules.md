# 后端架构专项规范

本文件用于把通用系统架构约束落实到 NestJS API、Worker 和后台进程。服务端新增/拆分服务、调整模块或数据所有权、引入网关/BFF、改变同步/异步协作时加载；普通用例实现不需要读取。

## 与通用架构规则的边界

- 本文件规定后端代码、进程、契约和数据边界如何落地；跨应用总体边界、技术选型和重大演进仍以 `docs/agent/architecture/rules.md` 为事实来源。
- 需求澄清、容量估算、成本或 ADR 额外读取 `docs/agent/architecture/system-design-rules.md`；部分失败、一致性、时钟、跨服务事务或高可用额外读取 `docs/agent/architecture/distributed-systems-rules.md`。
- API、数据、并发/消息、安全和运行环境分别继续加载后端及运维专项，不能把所有细则复制到本文件。

## 设计起点

- 先写清用户旅程、业务能力、数据所有者、写入不变量、调用方、运行负载和故障影响，再设计包、模块、进程或服务。
- 新能力默认进入现有服务的独立业务模块；边界尚未稳定时优先模块化单体，不为“以后可能需要”提前增加网络和运维边界。
- 不按用户量、团队人数、代码行数、文件数或语言套用架构等级；拆分只能由实际发布、扩缩容、故障隔离、合规、数据所有权或自治需求驱动。
- Monorepo/Polyrepo 是代码协作选择，不决定服务边界；目录分开不代表已获得独立部署、数据和故障隔离能力。

## 模块与分层落地

- 服务内按业务能力组织垂直模块；每个模块拥有术语、用例、领域规则、端口和适配器，不建立跨全局的巨型 `controllers`、`services` 或 `repositories` 目录。
- 保持 `presentation → application → domain ← infrastructure` 依赖方向；HTTP、CLI、定时任务和消息消费者都是入站适配器，只调用同一 application 用例。
- 外部数据库、缓存、队列、身份/支付 Provider 和时间/随机源通过出站端口接入；端口由业务需要定义，不能照框架接口或供应商 SDK 原样泄漏。
- 每个可执行入口只负责配置校验、依赖装配、进程生命周期和优雅停机；业务判断不得散落在 `main`、Module 装配或中间件中。
- 模块只暴露稳定用例、查询或版本化事件；禁止深层导入、共享可变实体、绕过用例写数据或通过全局事件总线隐藏循环依赖。
- 分层和映射以隔离真实变化与测试边界为目的；简单 CRUD 不机械增加接口、DTO 和空壳层，复杂领域则把关键不变量留在 domain，而不是全部堆进 application。

## 服务与进程拆分

- 独立服务必须拥有清晰业务能力和写入数据，能够独立构建、测试、部署、扩缩容、回滚和观测；需要锁步发布时应先修复契约或边界。
- API、Worker、Scheduler、Reconciler 可共享领域/application 代码，但只有生命周期、资源模型、权限或扩缩容不同才拆为独立进程。
- 新服务设计至少交付 Owner、契约、数据/Schema、依赖、SLO、容量假设、探针、限流/背压、降级、恢复和 Runbook。
- 网关只处理 TLS、路由、认证入口、粗粒度限流和协议适配；领域授权与业务不变量必须留在拥有数据的服务。
- BFF 只编排特定客户端所需的聚合和展示模型，不成为业务事实或跨领域写入的新所有者。

## 协作、事务与请求链路

- 调用方必须立即获得结果且失败要同步反馈时使用同步调用；事实通知、可延迟副作用和削峰任务使用持久化异步机制，不采用“能异步就异步”的绝对规则。
- 同步链路保持有界，逐跳传播截止时间、取消、身份和 Trace；不能在每层各自叠加无协调重试。
- 每类数据只有一个写入所有者；其他服务通过版本化 API、事件或只读投影访问，禁止跨服务写表、跨库 JOIN 和共享 ORM 实体。
- 单服务本地事务由 application 用例拥有；跨服务流程使用显式状态机、Outbox/Inbox、Saga/补偿和对账，详细失败语义按可靠性与分布式专项执行。
- 沿 `edge/gateway → presentation → application → domain → infrastructure` 标出超时、配额、信任边界和观测点；定位性能问题时按真实证据逐层分析，不能默认数据库、网络或框架是瓶颈。

## 演进与验证

- 从单体抽取服务采用绞杀式迁移：先建立兼容契约和新所有者，再迁移流量/数据并对账，最后删除旧写路径；禁止一次性重写核心系统。
- 架构变更同步更新模块图、依赖、契约、Schema、部署、权限、观测和回滚说明，过渡期明确权威写入源与退出条件。
- 验证至少覆盖依赖方向、模块公开入口、领域/application 单测、适配器集成、契约兼容、重复/超时/部分失败和关键链路 E2E。
- 新部署边界还必须实际验证独立构建、启动、探针、SIGTERM、容量/背压、回滚和故障隔离；只画架构图不能视为完成。
