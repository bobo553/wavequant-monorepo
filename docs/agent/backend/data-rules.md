# 后端数据与存储规范

本文件仅在任务涉及 PostgreSQL、迁移、事务、Redis、搜索或文件存储时加载，并继承 `docs/agent/backend/rules.md`。数仓、ETL、指标和分析数据集任务改读 `docs/agent/data-warehouse/rules.md`。

## 数据所有权与建模

- PostgreSQL 是业务事实来源；Redis、搜索索引、报表和读模型均为可重建派生数据，不得反向成为核心资源、计费、权限或审计状态的唯一真相。
- 每张表、Schema 和对象存储前缀必须有唯一业务所有者。服务之间禁止跨 Schema 写入、外键耦合或共享 Repository。
- 多租户或有资源所有权的数据从建模开始包含并约束对应边界；查询、唯一键、幂等键、缓存键和审计事件都必须保留该边界。
- 使用数据库约束守住最终不变量：`NOT NULL`、`CHECK`、`UNIQUE`、外键或等效校验不能只依赖应用层。
- 主键不承载业务语义；外部可见 ID 需评估可枚举性。时间字段、软删除、版本号和审计字段按领域需求定义，不机械复制模板。
- 金额存最小货币单位整数或定精度 `numeric`，同时保存币种；账本分录不可原地修改，通过冲正或补充分录更正。

## 查询、索引与分页

- Repository 暴露业务意图，不泄漏 ORM QueryBuilder 或数据库实体到 application/domain。
- 禁止字符串拼接 SQL；值使用参数绑定，动态表名、列名和排序字段使用代码白名单。
- 新索引必须对应实际查询、排序或约束，并用执行计划或压测证明价值；避免重复、低选择性和无消费者索引。
- 列表查询显式限定列、排序和上限，禁止无界 `SELECT *`、N+1 查询和把整表加载到内存后过滤。
- 大表优先 cursor/keyset 分页；排序键必须稳定并追加唯一键，确保翻页无重复和遗漏。
- 慢查询先定位执行计划、扫描行数、锁等待和往返次数，再决定索引、批处理、缓存或读模型，不能凭感觉优化。

## 事务与并发一致性

- 事务边界与单个业务用例一致并尽量短；事务中不得等待用户、调用外部网络、执行长计算或无上限批处理。
- 根据不变量选择乐观锁、行锁、唯一约束或原子条件更新；普通读写不得默认升级为全局/表级锁。
- 读取后更新的流程必须防止丢失更新。付费货币、库存、权益和存档版本使用数据库原子条件或版本列校验。
- 明确隔离级别能否满足幻读、重复读和写偏差需求；依赖特定数据库语义时添加集成测试。
- 死锁视为可预期的并发失败：保持一致加锁顺序、缩小事务，并仅在整个用例可安全重放时有限重试。
- 数据库提交与跨服务事件不能用脆弱的“双写”；使用同事务 Outbox，发布成功后再标记，消费者按至少一次投递设计。

## 迁移与数据变更

- Schema 变更只通过版本化迁移完成；生产环境禁止 ORM 自动同步或启动时隐式改表。
- 迁移文件可审阅、可重复执行并说明回滚/前滚策略；已在共享环境执行的迁移不得改写历史。
- 破坏性变更采用扩展—迁移—收缩：先新增兼容结构，再双读/回填/切换，确认无旧消费者后删除旧字段。
- 大表回填分批、可暂停、可重入并记录游标；控制锁时间和事务大小，避免一次迁移占满日志、连接或磁盘。
- 新增唯一/非空约束前先验证和修复存量数据；索引创建方式需评估写阻塞和磁盘空间。
- 删除数据、回滚迁移和生产执行必须遵守根规则的用户确认门禁；备份存在不等于恢复可用，关键迁移需有恢复验证计划。

## Redis 与缓存

- 引入缓存前记录要解决的瓶颈、事实来源、一致性容忍度、TTL、容量和失效策略；不能把 Redis 当默认数据库。
- Key 使用稳定命名空间并包含环境、服务、租户/资源范围、实体和 Schema 版本；禁止含 Token、邮箱或身份标识等敏感明文。
- 所有业务缓存必须有 TTL；批量生成时加入合理随机抖动，避免同一时刻集中失效。
- 采用 cache-aside 时先提交数据库，再使缓存失效；缓存删除失败必须有重试、事件或短 TTL 兜底并记录指标，不能静默吞掉；数据库已提交时不得把结果伪装成事务失败。
- 不存在的合法查询可短期缓存空结果并配合输入校验/限流防穿透；热点回源使用请求合并、互斥重建或逻辑过期防击穿。
- 缓存不可用时定义明确的失败或降级策略，并用限流/熔断保护数据库；禁止 Redis 故障时让所有请求无界回源。
- 分布式锁必须使用唯一所有者令牌、原子获取、有限租期和仅所有者释放；锁过期仍可能并发执行，关键正确性使用数据库约束或 fencing token。
- 缓存内容带版本并在反序列化时校验；命中率、延迟、淘汰、内存、连接和错误率必须可观测。

## 搜索索引

- 只有数据库查询无法经济满足的全文检索、相关性、分词或聚合需求才引入搜索引擎；先用真实数据和查询证明需要。
- 数据库保持事实来源，搜索索引通过 Outbox/CDC 或可重放同步构建；写 API 不对数据库和搜索引擎做无事务双写。
- 搜索文档包含来源 ID、租户/资源范围、Schema 版本和更新时间；权限过滤必须在查询端强制，不能依赖前端隐藏结果。
- Mapping、分词器、同义词和排序权重版本化；重大变更新建索引、回填校验后通过 alias 原子切换。
- 设计允许延迟与重复同步，定义可接受的索引新鲜度、失败重试、积压告警、对账和全量重建流程。
- 搜索结果仅提供候选 ID/摘要；涉及权限、价格、库存或支付状态时回源事实库复核。

## 文件与对象存储

- 用户上传、报表和媒体文件不得长期保存在容器/应用服务器本地磁盘；使用对象存储，数据库只保存受控元数据和对象 Key。
- Bucket 默认私有并遵守最小权限；公开访问通过受控 CDN 或短期签名 URL，签名范围绑定对象、方法、大小和有效期。
- 大文件优先客户端直传或分片上传，但服务端必须先授权对象前缀并在完成后校验元数据；客户端上传成功不等于业务已接收。
- 文件名由服务端生成 UUID/Hash Key，不信任原始路径；校验扩展名、声明 MIME、魔数、大小和业务配额，必要时隔离扫描后再发布。
- 禁止把用户提供的文件名拼入本地路径或对象 Key，防止路径穿越、覆盖和跨租户读取。
- 上传流程要处理未完成分片、孤儿对象、数据库失败和重复回调；通过生命周期规则和可重入清理任务回收临时文件。
- 静态不可变资源使用内容 Hash 与长缓存；私有或可变资源采用短缓存/版本 Key，避免 CDN 缓存越权内容。
- 敏感对象启用传输加密和服务端加密，并明确密钥权限、保留期、删除、审计和合规边界。

## 数据验证清单

- 运行迁移、Repository 集成测试、约束/事务并发测试和回滚或前滚演练。
- 使用真实查询形状检查执行计划、索引、分页稳定性和最大批量。
- 注入 Redis/搜索/对象存储超时与不可用，验证降级不会压垮事实库或泄漏数据。
- 验证缓存失效、重复事件、乱序事件、索引重建、孤儿文件清理和跨租户/资源隔离。
