# 数据采集与埋点专项规范

本文件用于客户端/服务端事件、埋点 Schema、采集 SDK、会话、曝光日志和分析数据入口。业务审计日志不能直接替代产品分析事件，反之亦然。

## 事件设计

- 每个事件定义业务目的、触发时机、生产者、Owner、消费者和废弃条件；没有明确决策用途的事件不采集。
- 事件名表达已发生的业务事实，字段使用稳定英文标识；Schema 必须版本化并通过共享契约或注册中心管理。
- 通用字段至少考虑 `event_id`、事件时间、接收时间、Schema/应用版本、环境、平台、匿名/用户标识、会话和必要上下文。
- `event_id` 或业务幂等键必须能支持去重；不能把客户端递增序号当作全局唯一标识。
- 区分事件时间、接收时间和处理时间，统一使用 UTC 保存；展示层再按业务时区转换。
- 属性枚举、单位、币种、空值语义和基数必须明确；禁止同一字段在不同事件中承载不同类型或口径。

## 身份、会话与隐私

- 匿名标识、账号、设备和会话分别建模；登录合并必须有确定规则、版本和可追踪映射，不能覆盖历史原始身份。
- 会话超时和跨端边界由产品口径定义并保持版本化，不能依赖分析工具默认值形成隐式指标。
- 只采集完成目的所需字段；敏感数据先分类、授权、脱敏或哈希，禁止采集密码、Token、支付凭据和输入框原文。
- 同意、撤回、删除和保留期要求必须传播到离线队列、明细表、聚合、索引和备份策略。
- 设备指纹、精确位置、未成年人数据和跨产品合并属于高风险采集，必须经过明确的隐私与合规评审。

## 发送与接入

- 客户端发送采用有界批量、超时和离线缓冲；页面关闭或进程退出时允许丢失非关键分析事件，不能阻塞核心交互。
- 分析事件默认按至少一次接收设计，入口负责鉴权、限流、大小限制、Schema 校验和去重；错误数据进入隔离而非静默修补。
- 关键支付、权益和审计事实由服务端权威事件产生，不能只依赖客户端埋点。
- 入口记录生产者版本、拒绝原因和延迟；Schema 不兼容、重复激增、流量异常和新鲜度下降必须可告警。
- 原始事件保留可重放形态；清洗、派生和聚合不能破坏回溯到原始输入的能力。

## 验证要求

- 上线前验证事件只触发一次或符合定义次数，并覆盖刷新、重试、离线、登录切换、版本升级和异常退出。
- 契约测试检查必填、类型、枚举、单位、时间、敏感字段和向后兼容；生产抽样只使用脱敏数据。
- 新旧版本并存时对事件量、去重率、缺失率、延迟和核心指标做对照，达到约定窗口后再删除旧 Schema。
- 曝光实验必须记录稳定分组、实际曝光时间、实验版本和互斥域，不能以“被分配”替代“已曝光”。
