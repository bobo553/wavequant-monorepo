# 数据建模与治理专项规范

本文件用于分析模型、元数据、血缘、质量、权限和生命周期。具体平台分层名称不是目标，稳定业务语义和可追踪性才是目标。

## 模型选择与分层

- 根据主要查询、关系、写入模式、时序、全文或向量检索需求选择关系、文档、图、时序或向量模型，不按热度选型。
- 数仓每层定义输入、输出、粒度和职责；可以采用 ODS/DWD/DWS/ADS 或其他命名，但不得机械复制无消费者的层级。
- 原始层尽量保留来源语义，标准层统一类型、主键、时间和枚举，消费层围绕稳定指标和用户任务建模。
- 事实、维度、快照、累计和聚合模型必须说明一行语义、更新方式、迟到数据和重算策略。
- 面向服务的宽表、语义层或数据集市只能来源于受治理模型，不能成为另一套不可追踪事实来源。

## 元数据与血缘

- 数据目录至少记录业务定义、技术 Schema、Owner、来源、消费者、更新频率、敏感等级、保留期和质量状态。
- 业务元数据解释“是什么和如何使用”，技术元数据描述结构与转换，运行元数据记录批次、耗时、行数和失败；三者不能混为注释。
- 血缘覆盖字段/数据集、转换代码、调度、看板、导出和模型输入；动态 SQL 或手工导出无法自动解析时补充显式登记。
- 破坏性变更前通过血缘识别消费者并提供兼容窗口；无人认领但仍被访问的数据不能直接删除。
- 指标、Schema 和数据集版本需要关联代码提交、运行批次和发布时间，保证历史结果可解释。

## 数据质量

- 质量维度至少按任务评估完整性、准确性、一致性、唯一性、有效性和新鲜度；每条规则有 Owner、阈值和处置动作。
- 阈值来自业务风险和历史分布，不照搬固定百分比；突变检测需要考虑节假日、版本发布和流量结构变化。
- 质量检查放在入口、关键转换和消费契约处；失败按影响阻断、隔离、降级或告警，不能用默认零值掩盖。
- 核心数据定期与权威来源对账，保存分子分母、差异样本和修复批次；仅比较总行数不足以证明正确。
- 修正历史数据时保留原批次、修复原因、代码版本和影响范围，确保可审计、可重放和可回滚。

## 权限与生命周期

- 权限按角色、数据域、敏感级别和用途最小授予；生产写权限、分析查询、导出和管理权限相互分离。
- 访问、下载、跨域共享和权限变更进入审计；临时权限必须设置到期并定期复核闲置账号与数据集。
- 生命周期覆盖创建、活跃、归档和删除；保留期同时作用于明细、聚合、缓存、索引、导出和备份恢复流程。
- 开发测试优先使用合成或脱敏数据；敏感生产数据不得为调试便利复制到个人设备或非生产环境。
- 删除和匿名化任务必须可验证下游传播结果，并明确无法立即清除的备份隔离和最终到期策略。
