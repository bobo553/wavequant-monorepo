# Python 工程规范

本文件是 Python 源码、服务、Worker、CLI、库和自动化脚本的规则入口。Python 项目仍按职责放入 `apps/servers/*`、`apps/tools/*` 或 `packages/*`；语言不是新增顶级目录的理由。

## 读取路由

| 任务类型                                    | 额外读取文件                           |
| ------------------------------------------- | -------------------------------------- |
| 任意 Python 实现、重构、依赖或配置          | 本文件全部基础规范                     |
| pytest、fixture、Mock、异步测试或覆盖率     | `docs/agent/python/testing-rules.md`   |
| 新建项目、构建、发布、CLI 入口或依赖分组    | `docs/agent/python/packaging-rules.md` |
| Python HTTP API、Worker、数据库或消息处理   | 对应后端/API/数据/可靠性/安全专项      |
| 数据管道、分析、模型训练、推理或 Agent 工具 | 对应数据数仓或 AI 规则                 |
| 容器、CI/CD、可观测、发布、事故处理或供应链 | `docs/agent/operations/rules.md`       |

跨领域任务组合实际命中的规则。例如 FastAPI 服务需要 Python 规则和相关后端专项，但不加载 NestJS 专属规则；普通数据脚本不因运行在服务端而自动加载全部后端规范。

## 项目边界与运行环境

- 每个可独立安装、测试或部署的 Python 项目以自己的 `pyproject.toml` 定义名称、Python 版本范围、依赖、构建方式和工具配置；不要把配置散落为互相冲突的多个事实来源。
- 应用和服务优先采用 `src/<import_package>/` 布局，测试放在项目根 `tests/` 并镜像主要模块；一次性仓库维护脚本可留在 `scripts/`，但不得承载长期业务核心。
- `requires-python`、Ruff `target-version`、类型检查器和 CI 测试矩阵必须表达同一兼容范围；升级最低版本时同步代码、镜像、文档和部署环境。
- 使用项目专属虚拟环境，推荐 `.venv`；虚拟环境、缓存、覆盖率、构建目录和本地解释器状态不得提交。
- 依赖必须通过项目选定的工具从 `pyproject.toml` 安装。应用/服务提交可复现锁文件；可发布库声明合理兼容范围，不把本机冻结列表当作公共依赖契约。
- 运行命令优先使用项目选定执行器，或在已激活虚拟环境中执行 `python -m <module>`；文档和 CI 不依赖全局 `python`、隐式 `PATH` 或用户级 site-packages。
- Python workspace 新增后创建 `progress.md`，并同步根 Harness 的发现、验证和 CI 编排，避免只被 pnpm workspace 发现逻辑遗漏。

## 格式、命名与导入

- 默认使用 Ruff 同时负责格式化、导入排序和 lint，配置集中在 `pyproject.toml`；不要长期并行运行 Black、isort 与 Ruff formatter 产生相互改写。
- 使用 4 空格缩进、UTF-8 和自动格式化；行宽由项目统一配置。工具能确定的纯样式问题不进入人工争论。
- 模块、包、函数和变量使用 `snake_case`，类和异常使用 `CapWords`，常量使用 `UPPER_SNAKE_CASE`；公共名称表达领域含义，避免无意义缩写。
- 标准库、第三方、本项目导入分组；优先清晰的绝对导入，禁止通配符导入和通过修改 `sys.path` 掩盖包结构问题。
- `__init__.py` 只暴露有意维护的公共 API，不用大规模重导出制造循环依赖或高昂导入副作用。
- 模块导入不得连接网络、访问数据库、启动线程、解析命令行或执行不可逆操作；入口行为放入显式函数，并用 `if __name__ == "__main__":` 保护脚本入口。
- 公共模块、类、函数和方法使用一致风格的 docstring，说明契约、异常、副作用和非显然约束；注释解释原因，不复述语法。

## 类型与数据模型

- 新增和修改的函数边界、公共 API、领域模型、回调与复杂容器必须有准确类型；局部显然变量依赖推断，不为满足形式机械标注。
- 一个项目选择并固定一种主类型检查器。默认可使用 mypy，严格度从新增/变更模块开始收紧；禁止用全局忽略一次隐藏整类错误。
- `Any` 只允许出现在无法控制的动态边界，并在最小范围内通过校验、`cast` 或适配器收窄；未知对象优先使用 `object` 后再通过类型守卫处理。
- 使用 `Protocol` 表达行为端口，使用 `TypedDict` 表达仍需保留字典形态的数据，使用 `dataclass` 表达内部值对象；外部输入必须经明确 Schema/DTO 校验后转换为领域类型。
- 可空、失败和缺失是不同状态。只有业务允许缺失时才使用 `T | None`，不要以空字符串、空字典或异常吞噬代替显式状态。
- 集合和返回值暴露所需的最窄协议，例如只读参数优先 `Sequence`、`Mapping` 或 `Iterable`；不要无必要泄漏具体可变容器。
- 类型忽略必须带精确错误码和原因，并尽量贴近第三方边界；新增无类型第三方依赖时优先安装或补充可靠 stubs，而不是扩大 `ignore_missing_imports`。

## 设计、状态与资源

- 函数保持单一职责，纯计算与 I/O 分离；业务规则不直接依赖 Web 框架、ORM、队列 SDK 或全局进程状态。
- 依赖通过参数、构造函数或清晰工厂注入。时间、随机数、文件系统、网络和外部服务应有可替换边界，使测试确定且可复现。
- 避免可变默认参数、隐式模块级单例和跨请求全局可变状态；需要缓存时明确键、容量、生命周期、并发策略和失效方式。
- 文件、连接、锁、事务和临时资源使用上下文管理器；获取与释放保持在同一抽象层，异常和取消路径也必须清理。
- 对大输入使用迭代器、生成器、流式解析或分块处理；只有测量证明必要时才引入并行或缓存优化，并记录内存与复杂度边界。

## 异常、日志与可观测性

- 只捕获能够处理、转换或补充上下文的具体异常；禁止裸 `except`、吞异常或用异常处理正常控制流。
- 自定义异常按稳定领域语义设计，并保留原始错误链：转换底层错误时使用 `raise DomainError(...) from error`；公开边界不泄漏内部堆栈和敏感实现。
- 清理逻辑使用 `finally` 或上下文管理器。重试只用于可识别的瞬态失败，并设置次数/截止时间、退避、抖动、幂等和可观测结果。
- 库代码获取模块级 `logging.getLogger(__name__)`，不自行配置根 logger；应用入口统一决定 handler、级别、格式和结构化上下文。
- 日志使用稳定字段并携带 trace/request/job ID；异常边界用 `logger.exception` 保留堆栈。不得记录 Token、Cookie、密码、私钥、个人信息或完整敏感载荷。
- 指标、日志和 Trace 围绕业务边界与外部依赖建立；健康检查不能只证明进程存在，还应区分启动、就绪和依赖退化。

## 并发与异步

- I/O 并发优先 `asyncio`，CPU 密集工作优先进程池、任务队列或原生扩展；线程与进程的选择必须基于共享状态、序列化成本和运行约束。
- 异步调用链不得直接执行阻塞网络、文件或 CPU 长任务；无法替换的阻塞调用放入受限执行器，并设置容量与超时。
- 并发任务必须有所有者、上限、截止时间和失败传播策略；优先结构化并发（如 `TaskGroup`），避免遗失的后台任务和无界 `gather`。
- 正确传播 `CancelledError`，清理后继续抛出取消；超时表示未知结果时不得盲目重试具有副作用的操作。
- 多协程/线程共享可变状态时显式同步；不要依赖 GIL、偶然原子性或事件循环调度顺序维护业务不变量。

## 安全边界

- 秘密从受控环境变量或秘密管理器注入，启动时校验；示例只使用占位值，错误和日志不得回显秘密。
- SQL 使用参数绑定，命令执行使用参数列表且默认 `shell=False`；用户输入不得直接拼接为 SQL、Shell、模板、路径或动态代码。
- 外部路径先规范化并验证仍位于允许根目录，上传内容同时限制类型、大小和存储位置；归档解压防止路径穿越与压缩炸弹。
- 不反序列化不可信 `pickle`，YAML 使用安全加载器；不得对外部输入使用 `eval`、`exec` 或不受限模板执行。
- HTTP Client 统一设置连接/读取/总超时、响应大小、重定向策略、TLS 校验和允许目标；服务端请求还需防 SSRF 与内网地址绕过。
- 安全相关随机值、Token 和比较使用 `secrets` 及恒定时间比较等专用能力，不使用普通伪随机数生成安全凭据。

## 最小质量门禁

按项目配置和改动风险运行等价命令：

```bash
ruff format --check .
ruff check .
mypy src tests
pytest
```

- 可发布包或构建型应用追加 `python -m build`，并在干净虚拟环境安装生成产物后执行 smoke test。
- 数据库、队列、网络和框架生命周期边界追加集成测试；并发、超时、迁移或安全变更覆盖对应失败模式。
- CI 与本地读取同一 `pyproject.toml` 和锁文件，不在命令行维护另一套规则；跳过或降级门禁必须记录原因、范围和恢复条件。
- 完成前更新功能状态与 workspace 进度，确认没有 `.venv`、缓存、覆盖率文件、构建产物、Notebook 输出或秘密进入变更集。
