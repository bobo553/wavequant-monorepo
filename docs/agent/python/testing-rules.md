# Python 测试规范

本文件仅在任务涉及 pytest、fixture、Mock、覆盖率、异步测试或 Python 测试架构时加载。通用测试策略仍以 `docs/agent/general/quality-rules.md` 为准。

## 测试布局与发现

- 使用 pytest 作为默认测试运行器，配置集中在 `pyproject.toml`；测试目录位于项目根 `tests/`，结构镜像 `src/<import_package>/` 的主要模块。
- 新项目优先使用 `--import-mode=importlib` 和 `src` 布局，测试真实安装包边界；不要靠修改 `sys.path`、工作目录或测试目录恰好可导入来掩盖打包错误。
- 测试文件命名为 `test_<behavior>.py`，测试名称表达前置条件、动作和预期；按行为组织，不复制生产目录中的每个函数名。
- 单元测试、集成测试、契约测试和慢速测试使用清晰 marker 分类，并在配置中注册；默认快速门禁不得因未知 marker 静默误分组。

## 用例设计

- 遵循 Arrange、Act、Assert，一个用例证明一个主要行为；使用参数化表达同一规则的输入矩阵，避免复制近似测试。
- 覆盖正常、边界、拒绝、空输入、重复、取消、超时、部分失败和已知反例；缺陷修复先增加能稳定失败的回归用例。
- 断言面向公开结果、状态变化和可观察副作用，不断言私有调用顺序或整段不稳定字符串；异常使用 `pytest.raises` 并验证必要语义。
- 高风险解析器、状态机、数值不变量和序列化可增加属性测试、模糊测试或差分测试，但失败样本必须可保存和重放。
- 覆盖率用于定位盲区并按风险设门禁，不以固定百分比代替关键路径、分支和失败模式的证明。

## Fixture 与测试数据

- fixture 表达可复用的测试前置条件或资源生命周期，不充当隐藏执行流程；默认使用函数级作用域，只有昂贵且安全共享的只读资源才扩大作用域。
- fixture 依赖保持浅且名称清楚，创建和清理在同一 fixture 中完成；生成器 fixture 的 teardown 必须在测试失败后仍可靠运行。
- `autouse` 只用于所有测试都必须满足的隔离不变量，例如阻止真实网络；业务数据和场景依赖显式声明。
- 使用工厂或 builder 生成最小有效领域数据，每个用例只覆盖与行为相关的字段；固定二进制/协议样本放入明确的测试数据目录并记录来源。
- 时间、时区、Locale、随机种子和环境变量必须显式控制；测试不能依赖本机时钟、执行顺序、用户配置或前一次运行残留。

## Mock、边界与集成测试

- Mock 只替换明确的外部端口，如支付、邮件或第三方 HTTP；纯领域对象优先使用真实实现，数据库/序列化/框架生命周期不能只靠 Mock 证明。
- Patch 生产代码实际查找名称的位置，并优先使用 `autospec` 或类型安全 fake；测试结束后由 fixture/`monkeypatch` 自动恢复状态。
- 网络请求默认禁止。需要验证 HTTP 协议时使用受控测试服务、录制的脱敏契约或适配器级 fake，并断言超时、重试和错误映射。
- 数据库集成测试使用与生产相同的数据库引擎和迁移，按用例隔离事务或 Schema；不以 SQLite 替代 PostgreSQL 特有约束。
- 契约测试验证请求/响应 Schema、兼容性和错误语义；跨进程 E2E 保留少量关键链路，失败时输出可诊断但不含秘密的证据。

## 异步、并发与进程测试

- 异步测试使用项目选定 pytest 插件并明确事件循环作用域；不要在同一调用链混用 `asyncio.run`、隐式 loop 和插件管理的 loop。
- 用事件、Barrier、受控 fake clock 或明确探针同步并发测试，禁止用任意 `sleep` 猜测任务已经运行。
- 验证成功之外的取消、超时、并发上限、异常传播和资源清理；任务结束后不得遗留协程、线程、子进程或打开的连接。
- 多进程测试为 Windows `spawn` 语义保留可导入入口和 `__main__` 保护；测试不得依赖 Unix-only fork 副作用，除非项目明确只支持该平台。

## 确定性与失败诊断

- 测试应可单独、乱序、重复和并行运行；共享端口、目录、数据库名和全局状态使用 pytest 提供的临时资源或唯一命名。
- 失败信息必须能定位输入、关键状态和边界结果；保留随机种子、参数 ID 与必要日志，不通过打印秘密或完整载荷换取可诊断性。
- Flaky 测试按缺陷处理：定位竞态、污染、时间或外部依赖，不能长期用重试、放宽断言或增加等待掩盖。
- 提交代码前运行对应项目完整 pytest；修改 fixture、插件、并发或公共契约时确认相关消费者也被提交前测试覆盖。日常修改后不运行 pytest，记录待提交前验证。
