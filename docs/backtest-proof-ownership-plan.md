# 回测证明的身份与内存归属方案

本文记录 002396 同口径回测的证明复用与计费边界，不改变三层共用算法、业务结果或公开字典契约。默认路径的有限性收据已实现，冻结版本 AB 完整回测约 289.8 秒，输出 hash 与对照一致，但总体尚未证明收益。驻留证明账本已完成源码和静态评审，完整测量待做；不能以代码接线完成代表 CPU 增长问题解决。

## 已有证据

- `owned_evidence.py::OwnedEvidence` 的 24 MiB 池强持已准入节点。池满后保留旧引用、拒绝新节点；新证明不能取得 `reference()`，于是 `finite()`、`_SignatureWriter` 和 `trend_judgement.py::_owned_value_bytes()` 重新展开池外证明。
- `PointVersion._record_sequence`、`_SourceTurn.source_record` 与 `PointRecord` 已能传递磁盘记录根，但上述三个入口仍只识别旧池身份。当前 record 通道没有独立证明“这些原生 Python 对象已由另一内存拥有者计费”。
- `ProducerRecordScope._capture()` 已按实际对象身份连接新图和旧字段引用；`PointRecord.matches()` 复核外壳、字段顺序及直接字段身份。此约定依赖内部生产者不再修改已移交的嵌套证明，不能认证任意外部字典。
- 记录存储接受 `bytes`，旧 JSON 有限性准入不接受。已有 `RecordRef` 不能直接等价于 `finite_evidence()` 已通过。
- 记录存储按实际身份追加，相等内容也产生不同记录；普通冷重建及 `_completion_evidence()` 的 deepcopy 会生成同值新容器。若直接用新记录 ID 替换嵌套签名字节，原先完整字节相同的证明也会被判修订，可能增加 cold miss。
- Y 普通升级检查点实验的第 2133 日累计耗时为 317.9561185 秒；账户及研究结果 hash 与对照一致。只有 82 次恢复，后段因容量拒绝不再恢复。普通来源消费增至 113304，完整预算扫描 409 次、20.9208 秒。原始证据保存在 `.codex-runtime/timing-002396/candidate-growth-y-nonstrict-full/days.jsonl`。
- Y 的冷分支仍完整重建 `ordinary.selected` 和 `regular`，随后 `_copy_runtime()` 接回旧 `merged`、key/origin 树、events、whole/pending/recent 引用。旧 runtime 与新 ordinary 可以持有两份实际不同的证明图；完整预算必须分别计费。`_freeze_runtime()` 还使当前工作容器提前进入持久树形态，撤销辅助缓存不会还原这些容器。
- `OwnedEvidence.publish()` 改变哪些子图具有请求内引用，`_SignatureWriter` 在这些子图上使用引用 token。恢复旧证明而重新生成普通证明会改变后续可用的对象身份及池准入顺序；具体额外冷重算中各因素的占比尚未隔离，不能仅凭总耗时断言全部来自某一种因素。

Y 默认关闭。只有显式 `_upgrade_checkpoints=True` 且启用尾部复用才建立实验实例；正常路径不执行实验 reset、finish、计数或额外预算计费。保留前缀但停止收新快照只能改善实验缓存失效，不能解决工作态的双图归属问题。

## 第一步：默认路径的当前来源有限性收据

`FiniteSourceReceipts` 已接入 `_OwnedSourceInputs.prepare()`。目标是让已认证的旧证明在共享池容量耗尽后仍能停止遍历；不改变签名字节、业务准入规则或证明载荷的内存归属，也不依赖实验性的 record 历史通道。

### 已实现协议与安全边界

1. 仅为 exact `CertifiedSource`、已 seal、与当前 `OwnedEvidence` 同 owner 的来源启用。来源的嵌套证明沿用既有内部生产者不可变契约；外部可变输入、未知来源及跨 owner 输入不借用收据。
2. 新点执行原 `OwnedEvidence.finite()` 循环，继续检查标准类型、有限数值、合法字典键及无环约束。只有该检查成功，或点本身已经是已认证的实际根，才允许登记；来源签名字节和 `RecordRef` 都不能代替有限性结论。
3. 收据只登记当前点及其直接容器字段的真实对象身份，不另建整图或每日版本索引。新尾遇到这些已认证根时跳过旧子图；同值新副本仍执行原遍历。旧不可变图不能在登记后新增指向新尾的回边，因此跳过旧根不会掩盖新图中的循环。
4. 来源修订时先检查并登记新尾，再撤销旧尾登记，允许新尾继续引用刚退出的旧尾证明。点登记次数与共享字段根引用次数分别管理；最后一个当前点不再引用时释放对应强引用。epoch token 防止旧条目撤销已换代的收据，不保留祖先版本链。
5. 收据元数据使用原来源输入缓存的 8 MiB 剩余额度。实例及统计固定余量、两张表的实际容量、ID、元组与计数均入账；record 模式还扣除版本载体元数据。容量不足只停止或撤销可选收据，保留原来源业务缓存和有限性检查。连固定外壳都无法容纳时释放 helper，仅留下禁用标记；不会逐日重建同一份已拒绝收据。
6. 所有签名及来源比较保持原语义，不用记录 ID 不等推断内容变化，也不让有限性收据为 `_owned_value_bytes()` 提供 8 字节载荷豁免。磁盘存储及有限性检查都没有替当前状态支付 Python 证明图的常驻内存。

### 当前实现与待验证项

- `finite_source_receipts.py`：检查结论、当前点和直接根生命周期、元数据准入及标量统计。
- `owned_evidence.py::finite()`：可选私有收据命中分支；无收据继续原检查。
- `trend_lines.py::_OwnedSourceInputs`：认证来源门禁、尾部登记/撤销及原 8 MiB 共账。
- `tests/test_finite_source_receipts.py`：共享旧证明、同值新副本、新尾非法值/循环、跨 owner、未封存来源、尾部替换/截短、预算拒绝和公共可变输入回退的回归源码；尚未执行。

统计字段为 `checks`、`root_hits`、`subtree_skips`、`registered`、`rejections`、`budget_rejections` 和 `peak_memory_bytes`，跨 clear 保留累计值。AB 全程测量已完成，有限性路径总体尚未证明收益，来源准备成本仍需分解；命中数只能证明该分支被使用，不能代替结果一致性、末段耗时与维护成本验证。

### 后续可选：record 持久有限性与生产者收据

持久 `json_finite` 标记与 typed 生产者收据属于后续独立方案，尚未接入默认有限性入口。若实施，新标量和新边须产生符合原 JSON 准入的独立结论，父记录才能从子引用合成；记录可存储的 `bytes`、非法 JSON 键不能自动取得有限性资格。clone/read domain 可以继承有限性，不能继承跨域容器身份。

同一已认证 carrier 只能作为未变化的正向证据；不同记录 ID 必须回退原完整字节比较。任何后续签名协议均须保留类型、字段顺序和跨字段/跨点 alias，不能以内容去重合并独立恢复域，也不能把公开恢复或历史 payload 编码暗中替换为相等性 token。该方案的成本与默认来源收据分开测量。

## 第二步：当前活图的增量内存归属

目标是把当前状态的内存核算从反复遍历证明图改为随实际新增和释放的节点维护。不能把 U2/Y 中“快照费用加当前整图费用”的保守重复计费重新包装为新账本。

### 已实现协议与安全边界

1. `trend_resident_proofs.py::ResidentProofLedger.register(anchor, root)` 使用实际 `_SourceTurn` 的弱引用作为锚，登记其 `source` 不可变证明图。普通状态只有内部 `_SourceVersion.owned_result` 才启用；正式状态要求 `_OwnedTrendJudgement`、已 seal 的 exact `CertifiedSource` 和当前活 owner。工作桶及外部可变输入不取得登记资格；没有新增生产者 `acquire(root_receipt)` 协议。
2. 每个节点按 `id` 加实际对象身份登记，保存直接边、`getsizeof` 费用和根/父边引用数。标准标量也按真实 alias 去重；同值新副本仍是独立图。账本强持登记节点，弱锚不会被 builtin 图反向保活；最后一个根/父边退出时增量释放节点。当前计费根未再引用但弱锚尚活的图，仍全额计入账本保活费用。
3. 普通和正式预算循环遇到已登记节点就停止展开。完整计费加上账本全部仍驻留的载荷、节点/边/弱锚元数据及表的实际容量；同一次遍历中先遇到、随后被登记的别名节点撤销重复费用。增量计费累计新增费用，释放不抵扣旧上界，因为同一图可能仍被未登记工作根引用；只有完整校准回收这部分保守上界。
4. 沿用旧池实际 `reference()` 的 8 字节边界，不借磁盘 ID 或有限性收据豁免载荷。owner 替换、关闭或节点表增长时失效可选索引。普通来源修订保留仍被真实锚持有的共享图，下一次完整核算包含这些图；显式 clear 释放索引，恢复旧检查点容量上界之前先撤销新版本索引。
5. 账本使用原状态额度中的至多一半作为自己的准入上限，未增加原状态总上限。容量拒绝保留已准入节点，只在实际释放达到已知所需空间时重试；空表拒绝后直接走旧计费循环。失败回撤仍为字典残留容量收费。总额触及原状态上限时，先撤销账本再走旧完整核算，随后才决定工作态是否确实超额。
6. 当前实现不改工作容器、证明生产、签名、public 输出或普通/严格算法，不重新启用 Y。普通选中点、正式升级完成点的只读性沿用现有生产协议；尚未覆盖无 `_SourceTurn` 锚的独立事件副本，不能据此声称全部证明遍历已经消除。

### 当前实现与待验证项

- `trend_resident_proofs.py`：真实身份 DAG、弱锚生命周期、保活载荷及元数据、容量拒绝和计数。
- `trend_judgement.py`：两个预算循环的私有接线、完整/追加费用合并、检查点恢复和原限额回退。Y 模块只在显式启用时导入。
- `tests/test_resident_proof_budget.py`：对照旧核算的共享 alias、独立同值图、弱锚/强保活释放、owner 扩充、未知对象、限额拒绝和先撤可选缓存的回归源码；尚未执行。

`stats` 跨 clear 保留累计的 `registered_nodes`、`registered_graphs`、`skipped_nodes`、`skipped_graphs`、`released_nodes`、`refusals` 和 `discards`，并报告当前 `memory_bytes`、`payload_bytes` 与 `peak_memory_bytes`。已完成静态自读及独立生命周期/计费审阅；完整冻结回测、维护成本和末段旧图遍历下降仍待测量，不作收益估计。
