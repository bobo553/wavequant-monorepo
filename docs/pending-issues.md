## Rust 资格对齐 Python 后的性能回退（v31 → v33）

归属：MONOREPO-362。责任模块：wavequant-quant-rs，采样与输出投影涉及 wavequant-api-rs。**重复全历史行情校验已优化，来源收敛及其余资格开销仍保留。** 下文的 v31/v33 表格是历史回退证据，详细数字以 [v31/v33 性能报告](diagnostics/guofang-performance-v33-2026-10-27.md) 为准；本轮改善见下面的新对照，不混用绝对耗时。

### 2026-10-27：已移除逐候选的重复全历史校验

分析入口以不可变 ValidatedCandles 保存已经校验的行情；各级资格借用同一前缀，新折叠 N 通过 observe_n_validated 进入共用规则核心。追加只校验新增部分及旧尾部边界，外部原始行情入口仍校验可见前缀。原 A/B/C、攻击、防守范围及来源收敛、资格重开规则均不改，原始全局索引不变。

同一国芳集团 2135 根日线，优化前 v33 与优化后各预热 3 次、交替采样 9 次。本轮新测：

| 阶段（中位数） | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 分析总计 | 170.2282 ms | 90.5433 ms | -46.8% |
| N／资格阶段 | 105.9954 ms | 35.1759 ms | -66.8% |
| 其中：二级资格消费者 | 87.6338 ms | 19.0758 ms | -78.2% |

七份输出逐字节一致：四级点数 [1433,236,16,2]、资格 7 段、共享 N 199 条，前端 VO 251131 B、节点表 303530 B、gzip 估算 42960 B、隔离 SQLite BLOB 68284 B 均不变。RSS 中位 33.39→33.36 MiB。完整方法、样本波动、阶段和缓存口径见[校验复用性能报告](diagnostics/n-validation-reuse-performance-2026-10-27.md)。本轮未重跑 Python 或浏览器，其他股票及多截止日等价仍未覆盖。

分析器仍需要来源反馈收敛、候选自身区间检查及较晚发现时的补推进；本轮没有单独微计时这些剩余工作。历史 v31 的资格错误不能用恢复旧规则换取性能，也不能把旧轮 43.1350 ms 与本轮 90.5433 ms 直接作为同机同轮比例。

随后用户明确新增 v34 规则：资格确认当天 K 线最低价被后续 K 线最低价严格跌破，资格在跌破日结束。该规则通过已有 startIndex 取价，每个活动窗口每日增加一次比较，无历史扫描或 DTO 增量。以上 7 段及逐字节一致性是 v33 性能优化的历史证据；v34 可能有意提前结束并影响后续重开，不再要求全部区间与旧 Python 相同。海洋王 2020-02-20 开始的窗口应在 2020-03-10 结束是用户提供的验收例，实际重算与性能尚待授权验证，不能沿用 v33 数字当作 v34 实测。

### 背景：为什么增加这些计算

用户要求解决国芳集团 601086 的 Rust 资格区间与旧 Python 不一致，并以 Python 为准。已推送的 f8a19fc / v31 在同一份 2135 根日线上输出 **10 段**二级资格，Python 为 **7 段**；按每日是否有资格展开，有 **469 个交易日不同**。因此，不能直接恢复较快的 v31 来解决性能问题。

v32 为修复差异补齐了共同逻辑，旧 Python 业务代码未改，也没有按股票或日期硬编码：

1. **保留整波冻结关键位。** 局部严格突破不能随意重置整波六态背景，避免生成较早且不属于该轮趋势的资格。
2. **补齐正式来源和上级回执。** 开放端点具备正式突破证明时参与严格通道；上级确认影响下级来源时，受影响层级重新计算，直到来源不再变化。一至三级继续调用同一个核心。
3. **分离 ABC 首 N 与资格重开候选，补充折叠 N。** 旧首 N 仍有效，不代表它能确认上次资格结束后的新窗口；较大组合中的折叠 N 也可能提供有效确认，原有共享首 N 不能覆盖所有确认通道。
4. **修正量价配对和结束时钟。** 量价通道读取 Python 的折线末跌高/低配对；历史来源修订按首次可知日结束资格，避免使用最终极值日期延后结束。

v32 在该冻结输入上恢复为 7 段，起止日、低点、结束原因与 Python 一致，每日资格差异降为 0。随后前端报“段六态时钟超过已知行情或早于端点”：正式通道替换了端点，却携带旧端点的六态日期。v33 将端点、六态、观察时钟一起更新，保留前端校验；该样本资格区间、共享 N 表及引用与 v32 原样一致。

**本项比较的是 v31 与包含上述修复的 v33，不能将全部回退归因于 v33 的时钟字段同步。** 问题是补齐正确性逻辑后的计算成本，不是只改了展示文案或 DTO。

### 同输入实测：慢了多少

样本为 sh.601086 国芳集团，2018-01-02 至 2026-10-23，共 2135 根因果复权日线。两版使用相同行情字节、有效配置和探针源码，Rust 1.98.1、dev profile（API/quant 的 opt-level=2）、默认 features。每版预热 3 次，再交替采样 9 次。四级结构全部计算，仅开启二级资格，不执行买卖或账户。

| 阶段（中位数） | v31 | v33 | 新−旧 |
| --- | ---: | ---: | ---: |
| **分析总计** | **43.1350 ms** | **139.1438 ms** | **+96.0088 ms** |
| 折线 | 15.9319 ms | 16.0597 ms | +0.1278 ms |
| 一级趋势核心，含该级重算 | 5.6152 ms | 18.0032 ms | +12.3880 ms |
| 二级趋势核心，含该级重算 | 0.3689 ms | 2.8340 ms | +2.4651 ms |
| 三级趋势核心，含该级重算 | 0.0345 ms | 0.1745 ms | +0.1400 ms |
| **N／资格总阶段** | **15.2276 ms** | **94.2884 ms** | **+79.0608 ms** |
| 其中：共享 N 总维护 | 10.1148 ms | 12.5664 ms | +2.4516 ms |
| 其中：二级资格消费者 | 3.2707 ms | 78.5472 ms | +75.2765 ms |

纯分析耗时为原来的 **3.23 倍，增加 222.6%**。v31 样本范围 **42.0324–66.5606 ms**，v33 为 **129.5427–228.2556 ms**。机器负载有波动，所有慢样本保留，不以最快值作结论。

“其中”是嵌套子阶段，不能重复相加；分项中位数也不能相加重建总中位数。三级外层调用包含其触发的一、二级重算，表格按各级累计 trend_kernel 统计，不能把外层 level3_ms 全部解释为三级算法变慢。

计时从分析器初始化至索引结果导出。**不含取数、复权、SDK、Redis、Worker 管道、HTTP、VO 投影、编码、缓存读写或图表渲染**；不能据此解释页面全部秒级等待。

### 原因：已确认事实和仍需定位的部分

**第一处增量是资格消费者，3.2707 → 78.5472 ms，应优先细分。**

- 新增 FoldedNs 只在折线来源变化时发现并去重组合，已经不是每天枚举完整历史；但**每个新发现的组合仍调用一次 observe_n**。
- 优化前 observe_n 先执行 validate_bars(&bars[..=end])，再次校验当前日之前的整段行情，再检查 A/B/C、攻击、防守等范围。该重复前缀校验现已移到入口复用；外部原始数组调用仍校验。
- 候选若被较晚发现，还需要从攻击日至当前日推进轧空状态；已有候选继续按日检查破位、超时及确认。独立资格重开候选也增加了维护工作。
- 资格消费者还包含独立量价、缺口、普通回撤和结束检查。源码确认存在上述工作，但**各项调用次数、扫描条数及净耗时尚未独立测量，不能把新增 75.2765 ms 全部归给历史校验或某一个 N 函数**。
- 共享 N 总维护只增加 2.4516 ms，不能将整个 94.2884 ms 都称为“共享 N 数组维护成本”。

**第二处增量是正式来源和上级回执引发的趋势重算。**

- advance_formal_indices 处理普通来源与带证明的正式来源；finish_hierarchy_arrays 收集上级回执，来源变化时重算受影响层级，直到没有新变化。
- “一至三级全部开启”不代表各级永远只调用一次。同版本缓存可以复用，来源版本发生变化仍会计算；本样本主要增量位于一级趋势。
- 正式点数从 [1433,152,14,2] 变为 [1433,236,16,2]。折线字段一致，一、二级几何及三级来源/时钟等改变；不是只新增状态列，也不是完全相同工作量。
- 收敛轮数、每级重算次数、重放前缀长度及缓存命中率尚未独立记录。不能宣称所有重算都能删除，也不能把循环上限当作实际执行次数。

**本次纯分析变慢不能归因于响应变大或 Redis 变慢。** 前端 VO JSON 为 253108→251131 B，节点表为 304074→303530 B，独立行情节点表保持 408946 B。隔离 SQLite 结果 BLOB 为 68223→68284 B；整进程峰值工作集中位数为 31.39→33.45 MiB，不是某个函数净分配。运行服务的 Redis 未参与这些分析计时。

## Rust N 维护及资格确认的剩余分析开销（v29 历史基线）

归属：`MONOREPO-362`。责任模块：`wavequant-quant-rs`。当前记录为后续待处理事项，本次仅整理文档，没有执行新的优化或测量。

### 问题与当前结论

2026-10-26 的 v29 测量显示，加入共享 N 维护和资格确认后，分析总耗时高于纯趋势计算。以下保留当时的开关成本及处理思路；当前 v33 的回退与原因见上面的新条目，不能把整套额外开销都归为“资格确认很慢”。

本次基线来自国芳集团 `sh.601086`，2018-01-02 至 2026-10-23，共 2135 根因果前复权日线。三组使用同一冻结二进制、同一行情字节；每组预热 3 次，独立进程轮换采样 9 次。

v30新增趋势悬停所需的N使用区间和目标变化快照；下列仍是已保存的v29基线，当时未单独测量v30开销。后续已有v31/v33的同输入版本对照，不能把两种不同问题的测量混作同一次实验。

### 已有事实和仍未确定的部分

- 三组完整四级趋势结果（含段六态与可知时钟）一致；开启／关闭资格时，完整 `nMemory` 和 `nRecords` 数据一致。开启组二级返回 6 条资格记录，其中 1 条确认当日结束；未据此确认与旧 Python 区间等价。
- 当前关闭买点资格开关仍会维护 N，供后续 ABC 判断等消费者使用。不能为降低数字直接删除 N 阶段，或将资格关闭组当作纯趋势。
- N 维护是本次较大的额外阶段，但现有计时不能证明其中某个转换、扫描或集合操作是主要原因，需要进一步细分后再决定修改位置。
- 资格消费者仍包含 N／ABC、独立量价、缺口、普通回撤及资格结束判断。各通道独立占比和历史扫描净成本，本次没有测出。
- 本次仅测算法分析，不包含 SDK／Redis 取数、复权、Worker 通讯、HTTP、VO 投影、编码压缩、缓存读写及图表渲染。页面若仍显示秒级等待，需要另外沿真实请求链路定位，不能将 44.4290ms 当作页面总耗时。

### 后续处理方向

1. 先拆分共享 N 准备、候选读取／去重、当前索引绑定、防守与轧空推进、目标推进的耗时及调用次数，确认 9.4500ms 主要花在哪里。
2. 拆分资格消费者中的 N／ABC、量价、缺口、普通回撤和结束检查，确认是否仍有可改为游标或累计状态的历史扫描。
3. 区分一次性来源整理与逐日工作；只在数据或状态变化时更新可复用信息。是否改造以实际计时为依据，保留当日可知时钟。
4. 优化后用同输入、同工具链、同 profile、同参数重新采样，报告总耗时、各阶段、波动范围和结果差异。若修改规则，先明确行为变化，不能把结果变化当作纯性能优化。

### 处理时必须保持的边界

- 同一趋势只维护第一条当前有效 N；严格破位后寻找下一条，新趋势切换自己的 N。跨级共用索引，历史记录不订阅每日维护。
- ABC 判断读取当日已经确认且有效的 N；不能用最终共享 N 状态回填历史，也不能仅凭 N 轧空直接开启交易资格。
- 不改变折线和一至三级共用趋势算法、资格开关含义、确认及结束规则，不更改旧 Python 业务。
- 后续取得相应验证授权时，对照完整四级结构、N 表及引用、资格区间与确定性；数据量或缓存变化另行测量，不从时间数字推算。
