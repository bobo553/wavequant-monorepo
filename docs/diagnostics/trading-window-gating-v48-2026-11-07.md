# 交易区间门控与重复计算修复（v48）

用户反馈国芳集团处理 279/2145 个交易日时，分析耗时 33.773 秒、后端总计 53.200 秒。这是用户提供的运行进度，不是本轮固定输入性能基准。

## 已定位的执行路径

- `trading.rs::evaluate_frame_with_timeframe` 在资格门控前，每日对四级历史三点组合调用 N 观察器，并重新回放缺口过滤和多类退出观察。它们不负责建立资格，却在无资格时照常执行。
- `day.rs::prepare_trading_day` 即使没有活跃窗口，也继续准备交易 N、目标生命周期、波段、候选证明和风险；旧信号历史还会延续区间外卖点扫描。
- `system.rs / execution/strategy_backtest.rs` 在确认是否需要交易观察之前复制可见历史、运行分钟观察；待买单的实际撮合缺少绑定窗口复核。

## 当前行为

普通买卖计算仅在已确认区间 `[start, end)` 内进行。资格推进与交易观察分开；无窗口时只维护必要的趋势/资格事实与日收权益，不调用交易 N、普通风险、候选或分钟选买。新窗口的交易状态从起点创建，停止补算此前空窗，并丢弃旧窗口候选；历史审计已经由系统逐日接收，不靠旧候选状态保存。

用户确认：结束时清仓，受 T+1、停牌或可卖数量限制的余量允许延后执行。账户据收盘后已确认的窗口状态发起退出，区间外仅继续这类既有退出；不得使用当日收盘才知道的关闭事实否认当天较早的开盘成交。所有入场在撮合前复核所属窗口，旧待买单不能跨关闭或被替换的区间。

历史结构仍是识别新区间的必要输入，不能全部停止。`compute_structure` 的确认事实计算保持原规则；本轮没有用最终数组区间倒填历史，也未将结构确认改成另一套判定。股票、一级至三级不加日期或标的特例，Python 源码不改。
