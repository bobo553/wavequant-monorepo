增量来源：

1. `kernel/observations.rs::observe_path` 在共同趋势扫描中保存当时可知的方向、关键位和翻转事件，读取点号并调用同一个 six_state_indices。一级总阶段显著增加；这是阶段差额，没有单独埋点证明其中每一毫秒都属于观察函数。此实现仍会重读已闭合的本级点号前缀，有进一步改成状态检查点推进的空间，不能声称全流程严格线性。
2. v26 只在买点开启级别内维护资格 N；v27 四级、双方向都维护结构 N 记忆，资格仍只对启用级别计算。新 N 记忆总成本中位 **27.0173ms**；分级中位见下表。

4. SQLite 冷写包括建表、压缩、事务和系统 I/O，新旧范围重叠；仅 13B 的压缩数据差不足以归因冷写的中位差。不把这次冷写当作运行中热点库的性能结论。

- nMemory 当前周期共 1 条二级首 N，其余级别当前新关键位周期内暂无首 N；这不是历史累计数量。旧版没有此字段，按 0B 计算，runtime 的 null 只是文件哨兵。
- 前端 VO 不包含 nMemory。VO 体积变化来自资格记录变化与版本字段；gzip/节点表具有整体压缩与去重效应，压缩后变大或变小不能由原 JSON 字节差简单推断。
- gzip 使用固定 mtime、level=6 的本地估算，不是浏览器 Network 实测；内部索引不是含 bars 的完整 Worker Envelope/SystemResult。timing 固定为零；独立缓存 BLOB 使用真实 ArtifactCache 编码，但共同固定 pipeline=null。
- 首 N 数据随内部结果保留，主要含 ABC 引用、颈线、攻击/确认日期、冻结防守和目标；不复制行情数组或递归历史证据。
